## Acceptance criteria

- σ per vertex from the spread of depth residuals across the frames that see it.
- Observed vertices whose σ exceeds a threshold are downgraded.
- Reporting the σ distribution on real golden objects is split out to **R-19**, since it needs
  the full chain run on real photographs (GPU Studio access), which this story's implementation
  session did not have. See notes below.

## Notes and decisions

_Written while working. What you tried, what surprised you, what you chose and why._
_If a decision here governs later work, add it to `docs/decisions.md` with a number._

2026-09-30: Implemented in `recon/uncertainty.py` (`compute_vertex_sigma`,
`downgrade_high_sigma_vertices`, `compute_sigma_distribution`, `uncertainty_run`, plus a CLI),
and `recon/provenance.py` gained `colors_to_labels` (the inverse of `labels_to_colors`) so this
story could recover R-09's per-vertex labels from `mesh_provenance.glb` directly. A few things
needed resolving before writing any code:

- **"Spread" = standard deviation**, per `docs/glossary.md` and D-006's wording ("σ per vertex is
  the spread of depth residuals across the frames that observe it"), neither of which pins down
  the exact statistic — std is the conventional meaning of σ, not really an arbitrary pick.
  Residual is `measured_depth_mm - z_cam_mm` per observation, exactly what R-09's docstring
  already promised this story would use. A vertex needs 2+ observations for σ to be defined;
  fewer gets `NaN`, not a fabricated zero.
- **The threshold is not σ_floor.** `docs/glossary.md`: σ_floor is "measured per reference tier
  in the October calibration study" — a number that doesn't exist yet, the same situation D-032
  already settled for I-01's tolerance-table fields. `DEFAULT_SIGMA_DOWNGRADE_THRESHOLD_MM`
  (3.0 mm) is this story's own configurable, unmeasured assumption, same pattern as every prior
  story's defaults (R-06's height threshold, R-07's voxel size, R-08's triangle count, R-09's
  triangulation angle).
- **"Downgraded" means relabelled Unobserved** — the pipeline only has two provenance states
  (`docs/glossary.md`'s Provenance entry); the proposal doc's fuller session-level "downgrade to
  Rescan" is I-07+ verdict logic, well downstream of this story. An already-Unobserved vertex
  can't be downgraded further, and a vertex with undefined (`NaN`) σ is left alone — absence of
  evidence of high spread isn't evidence of it, pinned by its own test.

**This story turned out unusually self-contained**, more so than R-06 through R-09: it depends
only on R-09's *persisted output* (`mesh_provenance.glb` for vertices/faces/current labels,
`observations.npz` for the raw residual data) — no camera poses, no depth maps, no re-running any
projection. The end-to-end test doesn't need to synthesize a fake capture run at all, just R-09's
own output contract directly.

**"σ distribution reported per golden object" is split out to R-19.** Same gap as R-06→R-17,
R-07→R-18: this machine has no GPU/torch and no local `fixtures/data/recon_runs`, so real
R-01→R-09 output for the five golden objects isn't reachable in this session. Everything this
story actually controls (the σ computation, the downgrade logic, the distribution statistics
function) is done and covered by synthetic-data unit tests (`tests/test_uncertainty.py`).

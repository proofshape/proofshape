## Why this exists

Interactive guidance and the later defect-aware guidance (proposal §8.1) both need to answer one
question: given the mesh so far, which camera position would see the most surface that hasn't
been properly observed? Proposal §6.2 defines the method: candidate views on a hemisphere, each
scored by how many under-observed vertices it would see, using Open3D raycasting on the CPU. D-022
puts this in the capture lane. Nothing computes it today.

## Acceptance criteria

- Generates candidate camera positions on a hemisphere centred on the board origin, each looking
  at the part: radius 25–40 cm and at most 60° from vertical, per proposal §6.2. The radius range,
  angle limit and sampling density are named, overridable constants.
- Scores each candidate by the number of under-observed vertices it would see unoccluded, using
  raycasting against the mesh, and returns the candidates ranked best first. "Under-observed"
  means R-09's `Unobserved` label after R-10's sigma downgrade (`recon/provenance.py`,
  `recon/uncertainty.py`'s `downgrade_high_sigma_vertices`). Reuse those definitions; don't
  redefine them.
- The core is a pure function over a board-frame mesh plus per-vertex labels. A thin CLI over a
  run directory, like the other `recon/` modules, is optional.

## Tests

Synthetic meshes, no GPU and no capture needed:

- A box with one face labelled unobserved: the top candidate must face that face.
- An occluder placed in front of that face: that view's score must drop.
- A fully observed mesh: every score is zero.

Open3D is deliberately **not** in `requirements.txt` (`recon/tsdf_fusion.py` imports it lazily
for that reason). The owner decides between two options:

- Add `open3d` so these tests run in CI.
- Raycast with something already installed.

Record the choice here. Tests that skip in CI and never run don't count toward the definition of
done.

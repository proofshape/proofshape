## Why this exists

Proposal §7.3: "When the buyer enters tolerances, each critical feature's tolerance is compared
with σ_floor for the reference tier the PO requires. Features below the floor are flagged
Unverifiable by this method before any photo is taken, so the buyer routes them to a CMM
knowingly instead of discovering endless Rescans in the field." §7.4 ties this to the parsed-spec
shape: "That structure feeds the ingestion pre-check directly: each tolerance is compared against
σ_floor for the required reference tier, and anything below it is declared Unverifiable before a
single photo is taken." The buyer-facing side already reserves this exact slot: C-16 says plainly that "tolerances aren't
yet checked against the method's noise floor (I-09, not built). It shows no Unverifiable flag,"
and separately lists "the intake pre-check's results, which I-09 adds to this page later" as out
of scope for itself. G-04's own "Why this exists" names I-09 directly: "The verdict logic
can't set tolerances without it (I-07, I-09)."

## Acceptance criteria

- Given an order's parsed spec table (§7.4's shape — `name`, `kind: hole|face|edge|overall`,
  `tolerance_mm`, `critical`, the same shape C-16 collects and R-34 stores), compares each
  feature's `tolerance_mm` against `k · σ_floor` for the reference tier the PO requires (the
  table's Unverifiable row: "tolerance < k·σ_floor for the reference tier this PO requires").
- Uses G-04's measured σ_floor for the board reference as the only real figure available at write
  time; σ_floor for the sheet/card tiers is an explicit, named gap pending G-10, not invented or
  assumed equal to the board figure.
- Runs at order/spec-entry time (`declared_at: intake`, before any session or photo exists),
  matching the glossary's "declared Unverifiable at intake, before any photo is taken" and the
  contract's own description of `declared_at: intake`.
- Tests, written with the code: a feature whose tolerance sits below `k·σ_floor` is flagged; one
  above is not; an order with no parsed spec yet produces no flag (D-004: no CAD/spec, no verdict
  machinery, nothing to check yet).

## Notes and decisions

- σ_floor for sheet/card tiers waits on G-10; this story should either explicitly gate on it, or
  scope its first pass to the board tier only and record the gap plainly rather than fake a
  number for the other two tiers.

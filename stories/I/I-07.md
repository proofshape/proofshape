## Why this exists

This is the decision the whole inspection lane exists for. Proposal §7.2 gives the exact table:

| Verdict | Condition |
|---|---|
| **Pass** | Every critical region Observed with σ ≤ tolerance / k, and no Observed deviation above tolerance |
| **Fail** | An Observed deviation exceeds tolerance by more than k·σ at that location |
| **Rescan** | A critical region is Unobserved or high-σ; registration is ambiguous; or the only deviation lies in an Unobserved region |
| **Unverifiable** | Declared at ingestion: tolerance < k·σ_floor for the reference tier this PO requires |

The hard rule governs every row: "Geometry that was not observed never fails a part and never
contributes to a Pass. It can only trigger a Rescan" (proposal §7.2; AGENTS.md). Issue #157 binds
this story specifically and explicitly: `compute_vertex_sigma` can return σ ≈ 0 from two
near-identical residuals at n=2 observations — "the 'zero spread means infinite precision'
trap... I-07 (verdict logic) must then use `max(σ, σ_floor)`, never raw σ, for every Observed
vertex... Done when: I-07's story file carries the `max(σ, σ_floor)` rule as an acceptance
criterion, citing this issue."

## Acceptance criteria

- Implements proposal §7.2's four-row table exactly for `declared_at: post_reconstruction`
  (Unverifiable's intake-time path is I-09/I-10's job), using I-06's per-vertex `_DEVIATION_MM`/
  `_DEVIATION_MEASURED` and R-10's per-vertex σ.
- For every Observed vertex, uses `max(σ, σ_floor)` — never raw σ — in both the Pass condition
  (σ ≤ tolerance / k) and the Fail condition (deviation > tolerance + k·max(σ, σ_floor)), citing
  issue #157 directly in the implementation.
- Produces a `VerdictResult` matching the frozen contract (`contracts/openapi.yaml`) exactly:
  `verdict` (`Pass`/`Fail`/`Rescan`/`Unverifiable`), `declared_at: post_reconstruction`,
  `orientation_ambiguous` (from I-05's `AmbiguityCheck.orientation_ambiguous`), `regions` (each
  with `name`, `provenance`, `deviation_mm` only when `observed`, and `contributes_to_verdict` —
  which must be `false` whenever `provenance: unobserved`, a structural rule
  `tests/test_contract.py` already enforces across every committed example), and `reason_codes`.
- `k` and σ_floor are consumed as inputs only (G-07's chosen `k`, G-04's measured σ_floor) — never
  invented or re-measured here; both stories reserve that measurement to the ground-truth lane.
- Tests, written with the code: synthetic (I-01) cases for each table row — a clean part → Pass;
  a planted deviation beyond tolerance → Fail; an Unobserved critical region, a deviation lying
  only in an Unobserved region, or an ambiguous orientation (I-05's s-05 case) → Rescan; a vertex
  with σ≈0 from n=2 agreeing observations is clamped to σ_floor rather than auto-passing (the
  #157 regression test, named explicitly).

## Notes and decisions

- Unverifiable's `declared_at: intake` path belongs to I-09/I-10, not here — this story only
  implements the `post_reconstruction` rows.
- Cite issue #157 directly in code, per the issue's own closing condition.
- **Two open points other stories already depend on, caught on review (@TabeenRaoof, #302):**
  - **What a "region" is in v1.** Proposal §7.4 says v1 "stops at the structured spec and applies
    tolerances globally, naming each feature in the report" — binding a named feature to an
    actual CAD region is the Tier 3 extension. But the contract's own committed examples already
    name a region `mounting_hole_A`. This story has to say where `regions` actually come from in
    v1 (named features applied globally, or something else) — not leave it implicit.
  - **The `reason_codes` vocabulary.** The contract leaves `reason_codes` free-form (`array of
    string`, no enum). C-15's plain-language reason-code table and A-09's narrative both wait on
    a real vocabulary existing; this story is what defines it.
- **Worth deciding at the Nov 13 boundary call, not decided here:** this story's Depends on puts
  G-07's 6 h on the critical chain that sets the date (G-01 → G-02 → G-08 → G-04 → G-07 → I-07).
  The verdict logic itself could instead be built and tested now against I-01's synthetic data,
  with `k` and σ_floor taken as *required* inputs (never defaulted) rather than measured here —
  the served verdict would then be gated on both values actually being recorded, without
  serialising the code behind the ground-truth measurements. That keeps D-003's rule intact
  (nothing runs for real without a measured `k`/σ_floor) while letting the logic itself start
  sooner. Caught on review (@TabeenRaoof, #302); not changed here since it's a scheduling
  decision for the team, not a unilateral one.

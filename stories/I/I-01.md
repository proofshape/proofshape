## Why this exists

The sprint plan built this to free the whole inspection lane from waiting on
reconstruction (§4 item 3): "load CAD → apply a random rigid transform → add Gaussian
noise at a chosen σ → delete a surface patch → label vertices observed/unobserved →
export. Produces exactly what reconstruction will eventually produce, months earlier."
It also makes every registration and verdict test fast and hardware-free (§8). And it is
the first real code in `inspect/`, so it puts D-053's package layout in place.

## Acceptance criteria

- **The package.** `inspect/` stays a bare directory with no `__init__.py` (D-030 holds:
  nothing shadows the standard library). The code lives at `inspect/inspection/`, and
  `pyproject.toml` lists `recon` and `inspection` explicitly and maps `inspection` to
  `inspect/inspection`. `tests/test_packaging.py` is strengthened to check that the
  standard library's `inspect` still resolves under `sysconfig`'s stdlib path and that
  `inspection.__file__` is under `inspect/inspection/`. This implements D-053, which
  records the layout and why the simpler ones fail.
- **The generator.** `inspection.synthetic` takes `(vertices_mm, faces)` and a seed,
  densifies the surface to a stated target edge length (the fixture CADs have 6–8
  vertices, which is nothing to add noise to), applies a random rigid transform, adds
  Gaussian noise at a given σ, deletes a surface patch, labels every vertex Observed or
  Unobserved, and writes the pipeline's own GLB format (`recon.mesh_cleanup.write_glb`
  with `recon.provenance`'s colours, millimetres, board frame: base at z = 0, body at
  z < 0) plus a sidecar JSON holding the applied transform, σ, the patch and the seed.
- **Tests, written with the code.** The same seed gives byte-identical output; the
  sidecar's transform maps the output back onto the CAD to within the injected noise;
  the patch's vertices are exactly the Unobserved ones; the written GLB reads back
  through `read_glb` and `colors_to_labels`.

## Tests

Unit tests in `tests/test_synthetic.py` and the strengthened `tests/test_packaging.py`, written
alongside the code (D-029). No manual check is needed.

## Notes and decisions

- σ, the patch size and the target edge length are parameters with stated defaults. They
  are not claims about the real method's noise; that is G-04's measurement.
- Why not `inspect/__init__.py`: `python -m pytest` puts the repository root first on
  `sys.path`, so a regular package named `inspect` there would shadow the standard
  library's for pytest itself. A bare directory is only a namespace package, which the
  import system tries last. And setuptools' `packages.find` cannot discover a package
  under a different name, so the explicit `packages` list is required.
- Takes `(vertices_mm, faces)` arrays rather than a path, so it doesn't depend on I-02.
  `recon.cad_size_check.read_ascii_stl` returns a vertex soup with no faces; the test
  builds its faces from the fixture STLs, or reuses `tests/test_next_view.py`'s
  `_subdivided_box`.

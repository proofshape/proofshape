## Why this exists

The sprint plan built this to free the whole inspection lane from waiting on
reconstruction (§4 item 3): "load CAD → apply a random rigid transform → add Gaussian
noise at a chosen σ → delete a surface patch → label vertices observed/unobserved →
export. Produces exactly what reconstruction will eventually produce, months earlier."
It also makes every registration and verdict test fast and hardware-free (§8). And it is
the first real code in `inspect/`, so it puts D-053's package layout in place.

## Acceptance criteria

- **The package.** `inspect/` stays a bare directory with no `__init__.py` (D-030 holds:
  nothing shadows the standard library). The code lives at `inspect/inspection/`, and
  `pyproject.toml` lists `recon` and `inspection` explicitly and maps `inspection` to
  `inspect/inspection`. `tests/test_packaging.py` is strengthened to check that the
  standard library's `inspect` still resolves under `sysconfig`'s stdlib path and that
  `inspection.__file__` is under `inspect/inspection/`. This implements D-053, which
  records the layout and why the simpler ones fail.
- **The generator.** `inspection.synthetic` takes `(vertices_mm, faces)` and a seed,
  densifies the surface to a stated target edge length (the fixture CADs have 6–8
  vertices, which is nothing to add noise to), applies a random rigid transform, adds
  Gaussian noise at a given σ, deletes a surface patch, labels every vertex Observed or
  Unobserved, and writes the pipeline's own GLB format (`recon.mesh_cleanup.write_glb`
  with `recon.provenance`'s colours, millimetres, board frame: base at z = 0, body at
  z < 0) plus a sidecar JSON holding the applied transform, σ, the patch and the seed.
- **Tests, written with the code.** The same seed gives byte-identical output; the
  sidecar's transform maps the output back onto the CAD to within the injected noise;
  the patch's vertices are exactly the Unobserved ones; the written GLB reads back
  through `read_glb` and `colors_to_labels`.

## Tests

16 tests in `tests/test_synthetic.py` (one or more per function below — determinism,
watertightness, the frame-flip sign and properness for any seed, noise bounds, patch connectivity
and size (and that the sidecar's recorded indices match the labels exactly, not just their
count), byte-identical GLBs for the same seed, GLB round-trip through `read_glb`/
`colors_to_labels`, and the sidecar transform recovering the original CAD surface within noise,
checked with a standard closest-point-on-triangle routine against a genuinely chiral fixture)
plus 2 new tests in `tests/test_packaging.py` (D-053's own acceptance wording), all written
alongside the code (D-029). No manual check is needed. Full suite: 495 passed. `ruff check .`
and `ruff format --check .` clean.

## Notes and decisions

- σ, the patch size and the target edge length are parameters with stated defaults. They
  are not claims about the real method's noise; that is G-04's measurement.
- Why not `inspect/__init__.py`: `python -m pytest` puts the repository root first on
  `sys.path`, so a regular package named `inspect` there would shadow the standard
  library's for pytest itself. A bare directory is only a namespace package, which the
  import system tries last. And setuptools' `packages.find` cannot discover a package
  under a different name, so the explicit `packages` list is required.
- Takes `(vertices_mm, faces)` arrays rather than a path, so it doesn't depend on I-02.
  `recon.cad_size_check.read_ascii_stl` returns a vertex soup with no faces; the test
  builds its faces from the fixture STLs, or reuses `tests/test_next_view.py`'s
  `_subdivided_box`.

2026-10-21: Implementation.

- **Package layout (D-053):** `inspect/inspection/__init__.py` plus `synthetic.py`;
  `pyproject.toml` now has an explicit `[tool.setuptools] packages = ["recon", "inspection"]`
  and `[tool.setuptools.package-dir] inspection = "inspect/inspection"`, replacing the old
  `packages.find`. `tests/test_packaging.py` gained the two checks D-053 itself specifies:
  the standard library's `inspect` still resolves under `sysconfig.get_path("stdlib")`, and
  `inspection.__file__` resolves under `inspect/inspection/`. `inspect/README.md` updated to
  past tense now that this has actually landed.
- **Frame flip, confirmed against existing code rather than guessed:** CAD files are z-up from
  z = 0; `recon/cad_size_check.py`'s own comment ("height above the board is `-z` relative to
  the fitted plane") and `tests/test_next_view.py`'s own comment ("+z points INTO the table")
  both independently confirm the board frame's height convention is the negative of CAD's. So
  the synthetic generator negates z once, as a *fixed* step, composed with the random pose
  (not applied randomly itself).
- **"Random rigid transform" is yaw-about-z plus an xy shift, not a full `SO(3)` rotation** —
  forced by the same physical fact I-03's own acceptance criteria already states ("the part
  rests on the board, so the free pose is yaw and an xy shift"). The fixed z-flip and this
  random component are composed into one rotation + translation, which is what the sidecar
  records as "the transform" — a single affine map from the loaded CAD's coordinates to this
  module's output, which is what lets a test invert it and check it against the original CAD.
- **"Deletes a surface patch" is implemented as labeling, not literal mesh deletion.** The mesh
  stays fully triangulated and watertight; a connected patch of vertices (grown by face-adjacency
  flood fill from a random seed) is labeled `Unobserved`, everything else `Observed` — matching
  real R-09 output's own shape (unobserved regions stay in the mesh, colored grey, never holes)
  and what `read_glb` + `colors_to_labels` downstream already expect.
- **Noise is applied along each vertex's own unit normal** (`recon.next_view.vertex_normals`,
  reused directly), not isotropic 3D noise — closer to how real depth-sensor noise behaves.
- **Densification** is uniform iterative 4-way subdivision (every triangle split via edge
  midpoints, with an edge→midpoint cache so shared edges get one shared new vertex, not a
  crack), repeated until the mesh's longest edge is at or below the target.
- **RNG:** `numpy.random.default_rng(seed)`. Grepped the whole repo first — no seeded-RNG
  convention existed yet to follow or clash with.
- Local environment note, not a code issue: `recon.next_view` imports Open3D at module level
  (D-047), and this machine was missing `libusb` (Open3D's dylib dependency) until
  `brew install libusb` — unrelated to this story, just a one-time local gap.

2026-10-21: @TabeenRaoof's review (PR #170) caught a real bug, numerically reproduced, and two
other gaps. Fixed, all in the same PR:

- **The CAD→board-frame flip was a mirror (`diag(1, 1, -1)`, determinant −1), not a rotation.**
  Every output part came out as its own mirror image — wrong winding, inward normals, and for a
  chiral part no rigid pose (all I-03 ever searches over) could register it against its own CAD
  again. @TabeenRaoof confirmed this by fitting a *proper* similarity from CAD to output on a
  chiral tetrahedron and an s-04-shaped prism: both came back with the sign of the enclosed
  volume flipped and tens of mm of residual, while `diag(1, -1, -1)` (a proper 180° rotation
  about x) fit at 0.0000 mm. Fixed to that. Added: `det(rotation) == +1` checked for 20 seeds;
  signed-volume sign preserved under the pose transform; and `_tetrahedron()` itself replaced
  with a scalene (genuinely chiral) shape, since the original's equal legs made it symmetric
  under axis swaps — its mirror image looked identical, which is exactly why the existing
  closest-point-to-surface test hadn't caught the bug.
- **The sidecar recorded only `patch_vertex_count`, not which vertices** — a same-sized but
  different patch passed all 16 tests unchanged. Added `patch_vertex_indices` to the sidecar and
  a test asserting set equality against the labelled `Unobserved` vertices, not just a count
  match.
- **The GPU service image no longer built**: `Dockerfile` copied `recon/` but not
  `inspect/inspection/`, and `pyproject.toml` now names `inspection` explicitly, so `pip
  install .` failed in the image build with "package directory 'inspect/inspection' does not
  exist." Added `COPY inspect/inspection/ inspect/inspection/` next to `COPY recon/ recon/`.
- Non-blocking, fixed anyway: `densify_mesh`'s convergence check now also runs immediately after
  each subdivision pass (not only before the next one), so reaching the target on the very last
  allowed pass returns instead of raising a "couldn't reach it" error that wasn't true; the
  duplicate `## Tests` heading in this file is merged into one.
- Noted, not acted on here (@TabeenRaoof flagged both as real but out of this story's scope):
  re-running `./scripts/bootstrap_dev_env.sh` is required after this merges, or `import
  inspection` fails for anyone on an existing `.venv` — worth a line in the progress-log entry
  at merge time; and `inspection.synthetic` paying for Open3D's import (via
  `recon.next_view.vertex_normals`) is a later cleanup candidate, not this story's problem.

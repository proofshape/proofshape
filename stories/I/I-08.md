## Why this exists

AGENTS.md's hard rule: "Geometry that was not observed can never pass or fail a part. It may
only trigger a Rescan. A model's guess must never approve or condemn a component. This governs
the verdict logic, the provenance labelling, and how the heatmap is coloured. Do not weaken it
for convenience." Weakening it is explicitly on AGENTS.md's refusal list. The sprint plan's S4
bullet names this story's two concrete jobs: "label completed surface Inferred and exclude it
from the deviation maths; enforce the rule that unobserved geometry never passes or fails a
part." A-04 already deliberately deferred half of this here: "The sprint plan's S4 Inspection
bullet put 'label completed surface Inferred' in the inspection lane. Defining the label moves
here [A-04], where the surface is produced; excluding it from deviation stays with I-06/I-07." So
this story is what makes the hard rule structurally true across both axes — Unobserved surface
*and* Inferred surface — rather than trusting I-06/I-07 to remember it informally each time.

## Acceptance criteria

- A region with `provenance: unobserved` never has `contributes_to_verdict: true`, and can only
  ever be a factor in a `Rescan` outcome, never `Pass` or `Fail` — checked as a structural
  invariant on I-07's actual output, matching
  `contracts/examples/getVerdict.response-200-rescan-unobserved.json`'s shape
  (`provenance: unobserved`, `contributes_to_verdict: false`, `sealing_face_not_seen` in
  `reason_codes`).
- Inferred surface (A-04's shape-completion output) is excluded from the deviation maths
  entirely: it never gets a `_DEVIATION_MM`/`_DEVIATION_MEASURED` value from I-06, and never
  appears in a `Region` with `contributes_to_verdict: true` — per D-005/D-006 and the glossary's
  Provenance entry ("Surface a generative model produced rather than a camera measured is
  Inferred: it never contributes to a verdict").
- **(Restated 2026-11-18, D-080 — see Notes)** A test fixture with a deviation lying only in an
  Unobserved or Inferred region never changes a verdict the session's real, measured evidence
  would otherwise reach, proved by comparing `compute_verdict`'s output with and without such a
  hidden defect, byte-for-byte identical. A session with no Observed, measured data at all still
  Rescans outright (`{name}_not_seen`) — the table's third row, at the only granularity v1 can
  express it (D-080: v1 has no per-feature CAD-region binding, so a defect hidden specifically
  within one feature's own unobserved area, while the rest of the session is measured, cannot be
  told apart from "nothing is wrong there").
- Tests, written with the code: a synthetic mesh (I-01) with Unobserved patches, and separately
  one with Inferred-labelled vertices stapled in, each run through I-07's verdict function and
  asserted to never flip to Pass/Fail on the strength of that surface alone — the regression
  suite for the hard rule, in the same spirit as R-29's Inferred-aware hard-rule test at the
  reconstruction layer.

## Notes and decisions

- This story is the enforcement point, not the label definition (A-04 already defines Inferred)
  and not the per-vertex computation (I-06/I-07 already compute deviation and verdict) — it is
  the cross-cutting invariant check that ties the two together.

### 2026-11-18: already true by construction in both I-06 and I-07; this story adds the tests,
not the behavior

Checked against the real code before writing anything new, not assumed from the title:

- **I-06** (`inspect/inspection/deviation.py`): `is_observed = model_labels == LABEL_OBSERVED`
  is an exact-match check, so Unobserved *and* Inferred are both excluded from measurement by
  construction. `tests/test_deviation.py`'s `test_compute_deviation_leaves_inferred_vertices_unmeasured`
  already pins this acceptance criterion, added on a review (#309) before this story was even
  claimed -- its own comment says so explicitly.
- **I-07** (`inspect/inspection/verdict.py`, PR #379): the `observed_measured` mask is the same
  `labels == LABEL_OBSERVED` check before either pool is built, so non-Observed vertices never
  enter a pool; only a `"Pass"`/`"Fail"` pool result ever sets `contributes_to_verdict`, and
  every other path leaves it `false`.
- **`tests/test_contract.py`** (R-29) already makes the hard rule structural -- but only over
  committed JSON examples, not `compute_verdict`'s own live output, which is the one real gap
  this story's acceptance criteria ask for ("checked as a structural invariant on I-07's actual
  output").

So no production code changed here -- `tests/test_hard_rule.py` is new, run against real
`compute_verdict` results across three fixtures: an Unobserved patch with a hidden defect, a
clean sample with an Inferred vertex stapled in and a large displacement planted on it, and a
fully-Unobserved mesh.

### 2026-11-18 (second pass): the first version's "resolution" of criterion 3 wasn't a decision
at all, and two of the three new tests didn't check what they claimed to (review, @mbj1994,
PR #384)

Two real findings, both from reading the actual code and the actual decisions log, not from
re-deriving the reasoning again:

1. **The first version of this file said criterion 3's "produces Rescan" wording was already
   resolved by "I-07's own 'what a region is in v1' resolution" and that this was "not a new
   team decision... applying one the team already settled." @mbj1994 checked `docs/decisions.md`
   directly and found no such decision recorded anywhere -- correctly: it never existed. What I
   pointed to was a note I wrote myself, inside I-07's own story file, while implementing I-07 --
   unobjected-to across two reviewers' four review rounds (none of which were specifically
   re-examining that framing; they were focused on numerical correctness bugs), but never
   actually agreed as a project decision the way D-073/D-077/D-078 are. Conflating "nobody
   happened to object" with "the team settled this" was the mistake, not the underlying
   reasoning. **Fixed properly: D-080** now records it as a real decision, and criterion 3
   above is restated to the invariant v1 can actually express, rather than left reading as an
   unmet criterion with an informal note papering over it.
2. **`test_hard_rule_holds_with_an_unobserved_patch_and_a_hidden_defect` and
   `test_hard_rule_holds_with_inferred_vertices_stapled_in` were partly vacuous.**
   `compute_verdict` only ever emits `provenance: "unobserved"` when `has_observed_data` is
   `False` for the *whole* mesh -- as soon as any Observed, measured vertex exists anywhere,
   every region comes back `provenance: "observed"`, regardless of whether the mesh also
   contains Unobserved/Inferred patches. So `_non_observed_contributing_regions(result) == []`
   passed in both tests for a reason that had nothing to do with whether the hidden defect
   actually influenced anything -- there were simply no non-`"observed"` regions in the result
   to inspect. Fixed: both tests now additionally run `compute_verdict` a second time on the
   *same* sample with the defect removed, and assert the two results are identical
   (`verdict`, `regions`, `reason_codes` all byte-for-byte equal) -- the real, non-vacuous proof
   that a hidden defect on non-Observed geometry cannot move the needle at all, which is what
   D-080 actually claims. The fully-Unobserved-mesh test's check was never vacuous (that is the
   one case where `provenance: "unobserved"` really is emitted) and now also asserts
   `verdict == "Rescan"` directly, matching the reviewer's own suggested invariant exactly.

## Why this exists

No CAD, no verdict (D-004). The proposal accepts STL, OBJ and GLB (§4) and today only
ASCII STL loads, through `recon.cad_size_check.read_ascii_stl`, which rejects binary STL
and returns a vertex soup with no faces. Registration needs indexed faces and normals.

## Acceptance criteria

- `inspection.cad.load_mesh(path)` returns `(vertices_mm, faces, units)` for ASCII STL,
  binary STL and GLB, deduplicating triangle soup into indexed faces. Anything else is
  rejected with a message naming the three formats. No new dependency: binary STL is
  numpy, GLB is `pygltflib` (already pinned).
- **No unit conversion for any format.** STL has no units by format and is millimetres by
  project convention. GLB is read as stored, reported as `assumed_mm`, because the
  pipeline's own GLBs (`write_glb`) hold raw millimetres although the glTF spec says
  metres. A GLB node with a non-identity `scale` is rejected, never silently applied. A
  buyer GLB authored in metres is a named limitation, handled by a `scale` parameter the
  caller sets on purpose.
- **Tests, written with the code:** both `fixtures/reference_cad/*.stl`; a binary STL the
  test writes; a `write_glb` output that round-trips unchanged; a scaled-node GLB that is
  rejected; an unsupported extension that is rejected by name.

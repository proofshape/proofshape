## Why this exists

R-06's acceptance criteria originally included "visually verified on every golden object; hands
and background excluded." That criterion needs real `points.ply`/`metric_alignment.json` for all
five golden objects (s-01..s-05) — the output of R-01 (VGGT) and R-04 (metric alignment) actually
run on real photographs — to look at. R-06 was implemented and fully unit-tested against synthetic
data on a machine with no GPU/torch and no local `fixtures/data/recon_runs`, so that look-and-check
step could not happen in the same session. Rather than merge R-06 with an unmet criterion, or block
it indefinitely on GPU access that has nothing to do with whether the segmentation logic itself is
correct, the criterion is split out here — the same move R-04 made for its known-size tolerance
judgment (see `docs/decisions.md` and `stories/R-04.md`'s notes for that precedent).

## Acceptance criteria

- For each of the five golden objects, `recon/part_segmentation.py`'s `segment_run` (or its CLI,
  `python -m recon.part_segmentation`) is run against that object's real R-01 + R-04 output.
- Each resulting `segmented_points.ply` is opened in a viewer (MeshLab, CloudCompare, or
  equivalent) and visually confirmed: the part is intact, and the board pattern, table and any
  hands/background clutter are excluded.
- Per-object result (pass, or what was wrong) is recorded in this story's notes below. A failure
  on a specific object is not automatically a defect in the segmentation logic — it may mean
  `height_threshold_mm` or the default footprint need adjusting for that object's geometry, both
  of which are already configurable parameters on `segment_part`/`segment_run`.

## Tests

This is the manual-check exception from `AGENTS.md`'s testing rule: "visually verified" is
inherently a human judgment on real photographs of real objects, not something an automated test
asserts. `recon/part_segmentation.py`'s own logic (the height/footprint predicate, the file I/O,
the alignment transform) is already fully covered by synthetic-data unit tests written alongside
it in R-06 (`tests/test_part_segmentation.py`) — this story is only the real-data look-and-check
that those tests cannot stand in for.

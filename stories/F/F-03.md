## Notes and decisions

Five operations (`createSession`, `uploadFrame`, `finishSession`, `getReconstruction`,
`getVerdict`), Tier 1 specified in full, the verdict result left an **envelope only** —
inspection (Phase 3) has no story files yet, so tolerance-table internals, `k`, and `σ_floor`
are marked `x-proofshape-extends-at` rather than invented. Ten examples committed, including two
non-happy-path variants (a no-reference reconstruction, a Rescan verdict with an unobserved
region) that the hard-rule test actually exercises.

Six tests written alongside each schema, not batched (D-029): valid-OpenAPI, every operation has
a committed example, every example validates against its own schema, the D-005 hard rule
enforced structurally (no `unobserved` region may have `contributes_to_verdict: true`), the
`Verdict` enum locked to exactly four values, and no example file orphaned from a real
`operationId`. Writing the "every operation has an example" test *before* filling every example
in caught a real gap before review did: four documented error responses had no example, and
`getVerdict`'s 404 case had no matching error code at all (`no_cad_uploaded`, added). All four
new tests confirmed to catch their own defect via mutation, reverted after each, before the PR
opened.

`CONTRIBUTING.md` (new) records the contract's change rule for *future* changes — full reasoning
in D-031 and D-032, including the reconciliation between this story's "all three approvals" and
the sprint plan's "two approvals" (GitHub can't count the author's own approval, so they're the
same rule stated two ways). That rule governs changes made *after* v1 is frozen; it does not
apply to this story's own merge, which needed and got the standard single approval — see the
completion record below and PR #16's review thread for why this needed spelling out explicitly.

## Why this exists

Proposal §12 item 4: "Robustness. Glossy, dark and thin parts; lighting variants; a hand in
frame; wrong part; photo of a screen; replayed session against a used code." G-02's own notes
already carve this exact scope out of the specimen batch on purpose: "Surface finish (glossy,
dark, thin-walled) is G-11's robustness set, because finish breaks reconstruction rather than
measuring its noise." A-01 already consumes part of this mechanism and names it directly: "Use
G-11's robustness set (screen photo, wrong part) for the manual check once it exists. No
accuracy, cost or latency is claimed from it." Today those two fixtures exist only as owner-local
files (`fixtures/data/vlm_checks/screen_photo.jpeg`, `wrong_part.jpeg`) used informally in A-01's
own manual check — this story is what formalizes and commits a reusable set, for A-01 and (once
it exists) A-02's veto testing both to share.

## Acceptance criteria

- Printed fixture set, on G-01's recorded printer and settings: at least one glossy-finish part,
  one dark-coloured part, one thin-walled part — chosen within G-02's convex-prism constraint
  where possible, or recorded as a deliberate exception where finish itself requires breaking it.
- A screen-photo fixture and a wrong-part fixture, captured as still images in the same
  `fixtures/` convention G-08 specifies (G-08 itself hasn't run yet; this story follows its own
  story's convention, not a precedent it's already set), formalizing (not duplicating) A-01's
  existing owner-local files, so A-01's manual check and any later A-02 veto testing have a
  shared, committed reference.
- Each fixture run through the normal reconstruction pipeline where applicable, with the failure
  mode recorded as a written result (does reconstruction degrade, does the VLM catch it) — not a
  pass/fail tolerance, since D-003 forbids an unmeasured tolerance claim.
- The written record cross-references A-01 directly, and (once it exists) A-02, so the
  robustness set's role as shared fixtures across stories is explicit rather than each owning a
  private copy.

## Tests

Written-check exception, same pattern as G-01/G-02/G-08: physical fixtures and captures are a
written record against these acceptance criteria, not a unit test. Any code written to classify
a failure mode gets its own tests alongside it.

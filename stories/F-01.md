## Acceptance criteria

- Repository is public, with a `LICENSE` and a `README`.
- `main` requires a pull request, one approving review, dismisses stale approvals on new commits, blocks force pushes, and **does not allow bypassing these settings**.
- A test pull request is demonstrably blocked until approved.

## Notes and decisions

Repository is `TabeenRaoof/proofshape`, public. Owner chosen as a personal account with the other
two as collaborators; going public removed the constraint that previously ruled out an
organisation, so this was a free choice rather than a forced one. Transferring to an org later is
supported if the team prefers.

All seven protection settings from D-013 applied via the API and read back to confirm. Two are
worth knowing about:

- **`enforce_admins` is on**, which is the point of item 7 — but it means *nobody* can bypass,
  including the repo owner. With only one collaborator today, no pull request can be approved by
  anyone. **This blocks every merge until the other two members are added.** That is the correct
  behaviour, not a misconfiguration, but it makes adding collaborators the immediate next action.
- **Status checks are enforced with an empty context list.** That gives us "branch must be up to
  date before merging" now, without requiring a check that does not exist yet. F-04 adds the CI
  job and its context name gets appended then.

Licence: MIT for our own code. The README records separately that the reconstruction weights
carry non-commercial research licences, which constrains commercial reuse of a deployed system
rather than publication of this repository.

## Why this exists

`UploadFrameRequest` (`contracts/openapi.yaml`) requires a `gyro` reading — `alpha`, `beta`,
`gamma`, all three — on *every* uploaded frame; it is not optional the way some capture features
are. On iOS 13+, reading device orientation at all requires an explicit,
`DeviceOrientationEvent.requestPermission()` call gated behind a user gesture — a platform quirk
that does not exist on desktop or Android, so it only surfaces on a real iPhone. If this does not
actually work there, no frame can ever be uploaded on the platform the whole product targets,
which makes it as load-bearing as the camera permission in C-02, not a secondary concern.

## Acceptance criteria

- On a real iPhone, tapping a button on C-01's page calls
  `DeviceOrientationEvent.requestPermission()` directly inside the tap handler; granting it shows
  live `alpha`/`beta`/`gamma` values updating on the page as the phone moves — the same shape
  `uploadFrame` requires.
- On a platform where this explicit request does not exist (desktop, Android), the page detects
  that and skips straight to reading orientation events, rather than getting stuck waiting for a
  permission API that platform never offers.
- Denial on iOS is tested too, and surfaces a specific, visible message rather than silently
  sending a zeroed or missing gyro reading — an `uploadFrame` call built on a fabricated reading
  would misreport the capture pose, and the contract requires the field regardless. What the user
  does next if genuinely denied (retry the prompt, abandon the session) is a real open question
  this story surfaces; it does not have to be solved completely here, but the case cannot be
  silently ignored either.

## Tests

Same reasoning as C-02: a device permission prompt on real hardware is the case `AGENTS.md`
names as genuinely unable to be economically automated. Record a written manual check — device,
iOS version, the steps taken, and the observed behaviour for both grant and deny — alongside
whatever of the platform-detection logic *can* be unit tested without a real device (for
example, that the code takes the "skip the explicit request" branch when
`DeviceOrientationEvent.requestPermission` is undefined, which is a plain feature-detection
check with no hardware dependency).

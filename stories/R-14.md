## Acceptance criteria

- Accepts a session's frames, returns the GLB and its metadata.
- Matches `contracts/openapi.yaml` exactly.
- Returns structured errors for the failure modes from R-02 and R-04.

## Notes and decisions

2026-10-01: Implemented the service as `recon/service.py`, using FastAPI as already called out
in `recon/README.md`. Session state is file-backed under `PROOFSHAPE_DATA_DIR` so R-15 can
containerize one process without needing a database story that does not exist. The default order-code
policy accepts any non-empty code; tests can inject a known-code set. That is deliberate: buyer/order
storage is not in the written backlog yet, so R-14 does not invent it.

`uploadFrame` parses D-041's `gyro` JSON Blob as its own multipart upload part. `finishSession`
requires at least three accepted frames because R-04's similarity solve has an algorithmic minimum of
three paired camera poses; this is not presented as a capture-quality measurement. Reconstruction then
runs R-02 → D-009-selected backend → R-04 → R-07 → R-08, and returns the generated GLB through the URL
in `getReconstruction`. R-14 also forwards its session-local `board_poses.npz` through the common
backend adapter so the COLMAP path from R-12 uses the right session instead of its fixture default.

The frozen F-03 `ReconstructionResult` schema has `status: failed` but no structured error
field. Changing it here would violate D-031. R-14 therefore persists the full R-02/R-04 ErrorDetail
(code/message/frame indices) in `session.json`; the public failed result stays schema-valid and repeats
the code/message in `warnings`. `observed_fraction` and `scale_agreement` are optional in the
frozen schema and are omitted when this dependency chain has no measured value rather than inventing
one. `getVerdict` returns the frozen `no_cad_uploaded` envelope until the inspection stories exist.

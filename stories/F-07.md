## Notes and decisions

2026-09-17: D-036 replaces the provider-specific "pod" wording with the shared Lightning GPU
Studio. The requirement itself is unchanged: the remote NVIDIA environment must be reproducible
with one command, alongside the Apple Silicon local path.

2026-09-21: F-05 shows `Ready`/`_unclaimed_` here and in the index because that is its true
state on `main` right now. The real close-out (@mbj1994, PR #21, GPU workspace verified by all
three members) exists on the unmerged branch `chore/close-out-f05-2026-09-21` — a previous pass
on this branch had instead hand-edited F-05.md to `Done` under the wrong owner with a blank
completion record, which has been reverted. F-05's dependency is satisfied in practice (the
shared GPU workspace is up and verified), so F-07 work is proceeding, but the story index will
only reflect F-05 as Done once PR #21 actually merges — don't let that state get hand-edited
again.

2026-09-21: Implementation. `scripts/bootstrap_dev_env.sh` is the one command: it picks
`python3.11` if present, else falls back to any `python3` that reports `>= 3.11` (refusing
otherwise with an explicit message, per the no-silent-failures rule), creates `.venv` if it
doesn't exist, and installs the project editable plus every pinned dependency in
`requirements.txt`. Verified locally on Apple Silicon (macOS, Python 3.11.16) from a fresh
`.venv`: bootstrap, `pytest -q` (15 passed), `ruff check .`, and `ruff format --check .` all
clean.

`ruff` was added to `requirements.txt` and to the `dev` extra in `pyproject.toml` — it wasn't
there originally, but AGENTS_START_HERE.md's pre-PR checklist requires `ruff check .` and
`ruff format --check .` every session, so a "reproducible dev environment" that doesn't include
the tool needed for that checklist isn't actually complete. Pinned to `0.16.8` (current at time
of writing) for reproducibility; note that `.github/workflows/python-ci.yml` installs ruff
unpinned, so CI and local can drift apart over time — out of scope for this story, flagging for
whoever next touches F-04/CI.

Not yet satisfied: acceptance criterion "verified by a second member from a clean checkout," and
running the bootstrap script on the actual shared GPU workspace (F-05) rather than just reasoning
that a POSIX bash script should behave the same there. Both need a second person and are part of
PR review, not something one person can self-certify.

2026-09-23: Lightning verification completed on the shared Studio. The first real run exposed a
platform-specific failure: Lightning's Studio already runs inside its managed Conda environment
(`cloudspace`, Python 3.12.11) and refuses creation of a second `.venv`. The bootstrap was
updated so the same command, `bash scripts/bootstrap_dev_env.sh`, reuses Lightning's managed
environment while ordinary macOS/Linux development still creates `.venv`.

After the fix, the Lightning run completed successfully. Verification on the shared Tesla T4:
`python -m pytest -q` -> 31 passed (2 existing `jsonschema.RefResolver` deprecation warnings);
`ruff check .` -> all checks passed; `ruff format --check .` -> 54 files already formatted;
and `bash scripts/start_gpu_workspace.sh` -> GPU CHECK: PASS with PyTorch 2.8.0+cu128,
CUDA available, one Tesla T4 visible. This satisfies the previously-missing Lightning half of
the one-command environment acceptance criterion.

## Why this exists

Three defects in R-08's cleanup (#183):

- **Inward-facing fills.** The hole filler builds each fill face running the shared boundary edge
  the same way as its neighbour. In a consistently wound mesh the two run it in opposite
  directions, so every filled patch faces inward, three.js culls it, and its normals are wrong.
- **Dropped components.** Cleanup keeps only the largest connected component, whatever the size of
  the others. The golden meshes are fragmented, so observed pieces of a real part vanish before
  provenance ever labels them.
- **Unenforced size limit.** R-08's acceptance criteria ask for a file under a stated limit. The
  limit is reported but never enforced: the CLI prints PASS and exits 0 when the file is over it.

R-07's Poisson fallback reconstructs from unoriented normals (#184). On a test sphere half of them
pointed inward, and the reconstructed radius spread far wider than with oriented normals. This
plausibly explains the cratered s-03…s-05 meshes R-18 recorded.

## Acceptance criteria

- Filled holes are wound consistently with the surrounding mesh.
- Dropping small components is a declared parameter: a minimum size relative to the largest, its
  default stated as an assumption. The dropped face count or area goes in the cleanup report.
- Over the file-size limit, cleanup re-decimates or raises, and the CLI exits non-zero rather than
  printing PASS.
- The Poisson fallback orients its normals before reconstructing. Orienting toward the cameras
  `fuse_run` already knows, or consistently across the tangent plane, is the owner's call; record
  it. The fallback is rerun on the golden objects R-18 called cratered and the result recorded.

## Tests

- **Winding:** after filling, no directed edge appears twice. Test a tetrahedron with one face
  removed and a larger loop. The current tests only check that loops close.
- **Components:** a legitimate second piece above the limit is kept, and one below it is dropped
  and reported.
- **Size limit:** the over-limit path is exercised.
- **Poisson:** surface accuracy on a known shape (for example, a sphere's radius within a bound),
  not just a non-empty result.

### Implementation decisions (2026-11-03)

- **Component threshold:** cleanup now keeps every connected face-component with at least **10%**
  as many faces as the largest component. This is a configurable cleanup assumption
  (`min_component_face_fraction`), not a measured tolerance. The cleanup report records the
  threshold, component counts before/after, and dropped face/component counts.
- **Hole winding:** each fill face traverses its shared boundary edge opposite the existing
  neighbour. Tests cover both a triangular hole and a larger centroid-fan loop.
- **File-size limit:** the configured GLB byte limit is now enforced. An oversized result is
  repeatedly re-decimated to 75% of its current triangle count; if it cannot meet the limit while
  retaining the minimum mesh, cleanup raises and the CLI exits non-zero instead of printing PASS.
  A CLI regression checks the non-zero/never-PASS behavior directly.
- **Poisson orientation choice:** the fallback estimates normals first. Full-rank point clouds use
  Open3D's tangent-plane consistency orientation. Exactly planar clouds bypass that path because
  Open3D 0.18 invokes Qhull/Delaunay there and rejects coplanar inputs; they receive a PCA normal
  instead. Those methods make the field internally consistent but leave one global +/- choice.
  Because board-frame up is -z and every capture camera is above the board, a decisive majority of
  strong +z normals is flipped as one field; a 25% vote margin avoids arbitrarily flipping closed
  or symmetric shapes. Regressions cover the sphere, an exact planar grid, a line-like cloud and
  an open-bottomed part-like cloud that must face board-frame up.
- **R-25 interaction:** provenance resolves normal sign independently per **winding group** —
  faces connected through shared manifold edges, the same adjacency used to propagate winding.
  For open winding groups, candidate camera→vertex pairs are batch-checked with one accelerated
  Open3D RaycastingScene before they may vote on the group's sign. The same geometric visibility
  filter is applied again to the final observation table, so an exposed part of a rear sheet may
  orient its group without allowing the covered part to become Observed. This check is independent
  of noisy measured depth and avoids per-pair full-mesh triangle scans.
  This is deliberately finer than shared-vertex connectivity: two sheets may meet at one bowtie
  vertex while keeping independent winding. Exterior closed groups use signed volume; a closed
  group geometrically enclosed inside another closed shell is treated as ambiguous and contributes
  **zero trusted normals** rather than guessing the material side of a cavity. This applies to both
  closed cavity shells and disconnected open cavity patches; only exterior open groups may use
  that group's trusted/depth-consistent visible pairs. Faces are flipped group-by-group before
  vertex normals are accumulated, so a shared bowtie vertex combines already-agreeing
  contributions. Regressions cover disconnected reversed pieces, the shared-corner bowtie case,
  a nested closed cavity shell, and a nested open cavity patch that must stay unobserved.
- **Golden rerun (2026-11-05, @TabeenRaoof; original review thread #236):** reran `fuse_run --method poisson
  --min-confidence 1.0001` on all five R-23-aligned golden objects against main and this PR.
  The oriented-normal output was visibly better on s-01, s-03 and s-04 (recognisable padlock
  body, rounded dome and prism respectively); s-02 also improved but retained a broad flat sheet.
  Median distance to the same run's marching-cubes mesh changed main -> this head as follows:
  s-01 5.8 -> 1.9 mm, s-03 2.3 -> 1.8 mm, s-04 3.4 -> 2.4 mm, s-02 5.1 -> 5.1 mm. The
  90th-percentile distance worsened on some objects because Poisson can close a sheet across the
  footprint. Open3D's exit-0/no-mesh failure is random across objects and reruns: on the
  round-2 head s-05 failed 6/6 while s-03 succeeded 2/3; on the final sign-fix head s-05
  succeeded on try 4 while s-03 failed 6/6. Open3D can print `Failed to close loop`, terminate
  with exit code 0 and leave no mesh. That pre-existing failure is tracked in #246 rather than
  hidden in this close-out.
- **Remaining Poisson limitation:** cleaned Poisson meshes still contain non-manifold edges and
  R-09/R-25 provenance rejects them (for example s-04 dropped from 1,456 raw non-manifold edges
  to 789 after cleanup, not to zero). That pre-existing end-to-end blocker is tracked in #247.
  R-27 therefore fixes the defects in its stated scope and records the fallback's remaining limits
  rather than claiming the fallback is already a provenance-labelled served-model path.

## Why this exists

R-04's similarity transform aligns R-01's reconstruction camera centres to R-02's board-posed
camera centres. R-22 found that whole scenes reconstruct 4–9% smaller than true size on all five
golden objects, and that the board-ruler scale (`recon.cad_size_check.measure_board_scale`) tracks
almost exactly with the ratio between the focal length R-02's board poses were actually solved with
and VGGT's own predicted focal, rescaled to the same pixel frame. The mechanism: a camera's
distance from the scene, in whatever units its pose source works in, scales with the focal length
assumed for that pose, so two pose sources disagreeing on focal length turns directly into a scale
error once R-04 fits their camera centres together. `height_ratio_over_board_scale` on s-04/s-05
(R-22) is 0.994/1.006 — this one mechanism explains essentially all of the measured height error.

R-04 does not need camera centres at all to fix scale: the board itself is already in every frame,
already detected by R-02 with known, exact geometry (D-034), and R-22's `measure_board_scale`
already demonstrates recovering scale directly from it, independent of either pose source's focal
assumption.

## Acceptance criteria

- R-04's similarity transform is anchored on the board's own geometry in the reconstruction (the
  same lifted-corner approach `recon.cad_size_check.measure_board_scale` uses — reuse it, or the
  Umeyama solve it already reuses from `metric_alignment.solve_similarity`, rather than building a
  second implementation of the same idea), not on camera centres. Record the chosen mechanism and
  why in this story's notes.
- On the golden set, `recon.cad_size_check.measure_board_scale` rerun against R-23's own output
  reports a scale within a few percent of 1.0 for all five objects (recorded per object; this
  story does not invent a tolerance — D-003 — it reports what the rerun actually measures).
- The board plane's z-offset and tilt after this change are recorded for all five objects. R-21 is
  blocked on knowing whether this removes most of the board-offset problem it exists to fix
  (R-21's notes point here) — don't duplicate R-21's own fix, just report what R-23's own output
  leaves for R-21 to still handle, if anything.
- Existing R-04 consumers (R-06 segmentation, R-07 fusion, R-09 provenance) keep working: a changed
  scale/rotation/translation convention in `metric_alignment.json` is still exactly what
  `apply_similarity_transform`/`apply_similarity_transform_to_extrinsic` expect, so nothing
  downstream needs its own change. If that's not achievable, say so and scope what else must move.

## Tests

Synthetic board-plus-camera scenes (the same style `cad_size_check`'s own board-scale tests use):
camera poses with a deliberately wrong focal length relative to the board's true geometry must
still recover a correct metric scale once anchored on the board, where the old camera-centre
approach would not. A case with too few usable board corners is an explicit error, not a silent
fallback to the old method.

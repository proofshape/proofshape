## Why this exists

The frozen contract gives `POST /v1/sessions` a 400 `ErrorDetail` for a malformed request. The
service only maps validation errors on `/frames`. Everywhere else FastAPI's default
`422 {"detail": [...]}` comes back, which the capture client treats as an undefined status
(#186). R-14's criteria say the endpoint matches the contract exactly.

The structural D-005 test in `tests/test_contract.py` only rejects `unobserved` regions that
contribute to a verdict. An `inferred` region marked as contributing passes, although the
contract says inferred geometry never contributes, and A-04 will start producing it (#187).

## Acceptance criteria

- A malformed body on any route returns that route's contract response (a 400 `ErrorDetail` for
  createSession), never FastAPI's default 422.
- The hard-rule contract test asserts `contributes_to_verdict` is false for every region whose
  provenance isn't `observed`.

## Tests

- `{}` and invalid JSON sent to createSession get a contract 400.
- A planted inferred-and-contributing example fails the hard-rule test, run against a temporary
  copy, not by committing a bad example.

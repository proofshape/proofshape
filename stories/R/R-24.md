## Why this exists

R-20 made R-01's point cloud and R-07's TSDF fusion agree on which pixels are trusted: both now
drop anything below the measured confidence threshold (D-045), using
`recon.vggt_runner.confidence_keep_mask` on `depth.npz`'s `depth_conf`. R-09's
`recon.provenance.compute_observations` reads the same `depth.npz` and decides whether a frame
"observes" a mesh vertex — the mechanism behind the hard rule (`AGENTS.md`: unobserved geometry
can never pass or fail a part) — but it never applies that same confidence check. A frame whose
measured depth at a vertex's projected pixel happens to sit at VGGT's confidence floor still
counts as an observation today, exactly like every other pixel.

This is not a regression R-20 introduced — `compute_observations` never read confidence before
R-20 either — but R-20 is what makes the inconsistency concrete: a vertex that R-07's fusion built
from zero trusted pixels at that location (because confidence excluded all of them) can still be
labelled **Observed** by R-09 if an untrusted pixel's projected depth happens to land within
`DEFAULT_DEPTH_CONSISTENCY_TOLERANCE_MM` of it. That is the hard rule's own mechanism accepting
evidence the rest of the pipeline has already decided not to trust.

## Acceptance criteria

- `compute_observations` only counts an observation from a pixel that also clears the run's
  confidence threshold — the same `confidence_keep_mask` predicate R-01 and R-07 already use, not
  a re-derived check. Where that threshold comes from (the run's own `run.json`, mirroring R-20's
  `fuse_run` default, vs. an explicit override) is the owner's call; record it.
- `provenance_run` is re-run on all five golden objects. Record the per-object change in
  `observed_fraction` beside R-20's and R-09's own numbers, so the effect of this story is visible,
  not assumed.
- R-10's `uncertainty_run` (which consumes R-09's `observations.npz`) is also re-run on all five,
  since fewer trusted observations can change `sigma_mm`'s distribution. Record whether R-19's
  sigma findings still hold or need updating; if they change materially, say so rather than
  letting a stale number stand.

## Tests

Synthetic vertices/frames where a frame's projected depth is within tolerance but its confidence
is below threshold: that frame must not count toward the vertex's observation count, and a vertex
that only had such frames must end up Unobserved, not Observed. A control case (confidence ignored)
must show the opposite, so the test is known to catch the regression — same pattern as R-20's own
`fuse_run` confidence tests. The golden-set rerun is a manual check, the same exception R-17/R-18
use: judging whether `observed_fraction`'s change is sensible is a human call, not an assertion.

## Notes and decisions

2026-10-11 (when written up, from R-20): R-20's own notes have the full context — this is the one
acceptance-criterion gap it deliberately left out of scope, since changing `observed_fraction` and
R-10's sigma distribution touches two other stories' settled output and deserves its own review
rather than riding in on R-20's diff.

2026-10-15 (implementation):

**Where the threshold comes from — the owner's call, recorded here: the run's own `run.json`
by default, an explicit `min_confidence` overrides it.** Exactly `fuse_run`'s rule, chosen over
two alternatives. *Explicit only* would push the same `run.json` read into `service.py`, which
doesn't know the threshold either. *Reading `tsdf_fusion.json`* would agree with fusion even when
fusion was overridden, but provenance labels R-08's `model.glb`, which has no link back to the
fusion report, so it needs a new required path and couples R-09 to R-07's report layout. Reading
`run.json` means that in the service pipeline (which passes no threshold to either stage) fusion
and provenance trust the same pixels by construction. The one way they can still disagree is a
caller overriding one stage and not the other, and each report now records `min_confidence` and
`min_confidence_source` side by side, so that is visible rather than silent. No new D-number:
this applies D-045's threshold and R-20's existing rule to one more caller, it doesn't decide
anything new.

**One resolver, not two copies.** R-20 wrote the `run.json`-or-override logic inline in
`fuse_run`. Copying it into `provenance_run` would recreate the drift risk R-20's own shared
predicate exists to prevent, so it moved to `recon.vggt_runner.resolve_min_confidence`, next to
`confidence_keep_mask`, and both stages call it. `fuse_run`'s behaviour is unchanged, and R-20's
six `fuse_run` confidence tests still pass against the helper.

**`compute_observations`' mask is required, and must be boolean.** It takes a keyword-only
`trusted_pixel_mask` (`confidence_keep_mask`'s output) with no default: defaulting to "trust
everything" would let a future caller drop the hard rule's check just by not passing it. Unlike
`fuse_tsdf`'s `keep_mask`, it is rejected rather than coerced if it isn't boolean. Passing the raw
`depth_conf` by mistake would otherwise coerce VGGT's untrusted floor of 1.0 to `True` and trust
exactly the pixels the mask exists to drop. Trust is looked up at the same rounded pixel as the
measured depth, so it always refers to the exact sample being compared. `observations.npz`'s
layout is unchanged, so R-10 needed no code change.

**`provenance.json` gains** `min_confidence`, `min_confidence_source` and
`confidence_dropped_pixel_count` (same names and meanings as `tsdf_fusion.json`), plus
`observation_count` (rows in `observations.npz`). The CLI gains `--min-confidence`. A `run.json`
that is missing or predates the field is now a named `R-09 PROVENANCE: FAIL`, not a traceback.
`service.py` needed no change: `fuse_run` has already validated the same `run.json` by the time
provenance runs.

**Tested that the tests catch the regression**, R-20's pattern: with the `& pixel_trusted` line
removed from `compute_observations`, four tests fail — the `compute_observations` trusted/untrusted
pair, the story's required end-to-end case (both of a vertex's frames at VGGT's floor, run.json at
1.0001 → Unobserved; override 0.0 → Observed), the per-frame case, and NaN-at-threshold-0.0.
Restored, all pass. Full suite: 404 passed, 1 skipped (`main` before this story: 388 passed,
1 skipped).

**A local test-ordering crash, not caused by this story.** On this Mac,
`pytest tests/test_vggt_runner.py tests/test_tsdf_fusion.py` (that pair, in that order, in one
process) dies with a native segfault: the trace shows `torch._C` loaded alongside skimage's
marching cubes. Reproduced on a clean `main` checkout, so it predates R-24; each file passes on its
own, and the full suite (different order) passes. Worth knowing before anyone reads a crash
there as a regression.

**Golden-set rerun (manual check).** Run locally on the existing `fixtures/data/recon_runs/<s>/`
(git-ignored; outputs under `<s>/r24/`). For each object:
1. `fuse_run --min-confidence 1.0001` on current code. R-20's saved meshes predate R-21's
   height cut (their `tsdf_fusion.json` has no `board_surface`), so they were re-fused.
2. R-08 `cleanup_run` → `model.glb`, the mesh `service.py` actually labels.
3. `provenance_run` twice on that same mesh: at 0.0 (**t0**, the pre-R-24 behaviour) and at 1.0001
   (**R-24**).
4. `uncertainty_run` on each.

The override is needed because these runs' own `run.json` records 0.0: they were made before
D-045. A fresh R-01 run records 1.0001, and the default path picks that up with no flag.

**Reading it.** On every object the change goes only toward Unobserved, the direction the hard
rule allows. A rise would have meant a bug. Confidence removed 2.8–4.5% of observations, and
`observed_fraction` dropped by 0 to 0.54 percentage points (s-03 most). The s-01 fraction is
unchanged even though six vertices dropped: `observed_fraction` counts faces whose three vertices
are *all* Observed, and none of those six were in such a face.

The effect is small despite 3.8–4.6 M pixels per run sitting below threshold. That is consistent
with the mesh itself being fused from trusted pixels only (R-20), so its vertices sit where
trusted depth was. The untrusted pixels that *were* vouching for vertices are the residual this
story closes. I've given that as an interpretation, not a separate measurement.

The low absolute fractions (about 10–40% Observed) are R-09's existing behaviour on these meshes,
not something R-24 moved. R-18 and R-20 already found these meshes don't yet close into a
recognisable part. They are recorded here as measured, not judged.

**Does R-19's finding still hold?** Its *finding* does. R-19 concluded that the unmeasured 3.0 mm
threshold downgrades "neither nearly everything nor nothing" (2.0–16.9% then) and so should not be
retuned on one run. Here it downgrades 3.8–8.5%, still neither extreme. R-24's own effect on
sigma is negligible: on the same mesh, mean, median and p90 each move by at most 0.02 mm.

**R-19's per-object *numbers*, however, no longer describe the current pipeline, and that is not
because of R-24.** R-19's counts came from Studio runs (2026-10-05) on meshes made before R-20's
confidence filtering and R-21's height cut. R-19 also doesn't record whether it labelled R-07's
raw mesh or R-08's cleaned one; this rerun labels R-08's, as `service.py` does. On today's meshes
the Observed counts differ several-fold (s-04: 1,294 there vs 6,056 here; s-01: 6,811 vs 1,259),
and mean sigma differs by as much as 0.56 mm (s-04: 1.834 → 1.276 mm). Since R-24 moves sigma by
at most 0.02 mm on a fixed mesh, the difference comes from the mesh, not from this story. The
tables above are the current-pipeline numbers; a dated pointer is added to R-19's notes so its
table isn't read as current.

*One gotcha for the next person running this:* the venv has an editable install of `proofshape`
pointing `recon` at the main checkout. A script run from a git worktree therefore silently
imports the main checkout's code, not the worktree's (`python -m pytest` from the worktree is
fine, since the cwd comes first). The first pass of this rerun did exactly that and failed loudly
on the new `min_confidence` argument. It was discarded and rerun with `PYTHONPATH` set to the
worktree, plus a guard that refuses to run unless `recon` resolves there.

## Why this exists

Found on review of G-04/PR #348 (@TabeenRaoof), not invented here: `recon/cad_size_check.py`'s
`measure_prism` and `_fit_rigid_2d` both have real, pre-existing bugs that make per-edge length
measurements untrustworthy, independent of G-04's own extension.

1. `measure_prism`'s edge length is the 2nd–98th-percentile point extent along the edge, which
   reads a perfect, noiseless, reconstruction-free prism about 4% short of its true corner-to-
   corner length by construction (confirmed by densely sampling each G-02 CAD's own walls with
   no noise and no reconstruction at all, then running `measure_prism` on that alone). A caliper
   reads corner to corner; this convention mismatch biases every edge negative before any real
   error enters.
2. `_fit_rigid_2d`'s exhaustive discrete pose search can land in a visibly wrong pose for a right
   triangle (`g02_03`) and a square (`g02_01`), confirmed against the point cloud directly, and
   is not stable run to run on identical input — a tiny reconstruction difference can flip which
   discrete candidate scores best, landing a *qualitatively* different pose, not a numerically
   close one.

Both block any story that needs a real edge-level error figure — G-04's board-reference σ_floor
today covers height only, with no measured floor for in-plane features (edge lengths, wall
positions), and R-16/I-07 both need exactly that (D-073).

## Acceptance criteria

- Edge length is measured corner to corner (matching a caliper's own convention): fit each
  footprint wall's line from its inlier points, then take the edge's length as the distance
  between its two adjacent fitted wall lines' intersections, not a percentile of point extent.
- `_fit_rigid_2d`'s pose search is robust on `g02_01` (square) and `g02_03` (right triangle) —
  the two real reproduction cases from PR #348's review — and on re-run, gives the same pose
  twice on the same input (checked, not assumed).
- A synthetic test samples a perfect prism (no noise, no reconstruction) and confirms the new
  edge measurement is within about 0.2 mm of the CAD's true corner-to-corner length — the
  regression test for the bug this story fixes.
- G-04's own `caliper_edge_errors` aggregate is re-run against the fixed functions once this
  lands, and the result (in-plane σ_floor, or confirmation it's still not measurable) is
  recorded as its own decision, updating D-073's "no measured floor yet for in-plane features."

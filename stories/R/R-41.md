## Why this exists

X-03 (I3) has to show "a substituted part caught on scale". `check_scale_agreement`
(`recon/scale_agreement.py`) gets one of its ratios backwards (#181), so it can't be trusted for
that.

- The caliper ratio is `caliper_reading_mm / board_pitch_mm`, which is true printed pitch ÷
  nominal.
- The CAD ratio is `1 + cad_registration_residual`, which is model ÷ CAD.
- The reconstruction assumes the nominal pitch. So a page printed small makes the model come out
  large by the reciprocal factor: model ÷ CAD = nominal ÷ true.

So two sources that agree get flagged, and two that contradict each other get missed. #181 gives
both cases:
- a 98.8% print reads 0.988 against 1.012, a 2.4% gap, and is flagged;
- caliper 1.015 and r = +0.015 contradict each other but show no gap.

`tests/test_scale_agreement.py:46-58` encodes the same convention, so it passes.

## Acceptance criteria

- **The team agrees the fix before it merges**, because it changes the formula D-039 records.
  The agreement is noted in this story, and D-039 gets a dated amendment saying what changed and
  why. Don't rewrite D-039's original text.
- `check_scale_agreement` compares the CAD source as the same quantity as the caliper's, true
  pitch ÷ nominal. #181 suggests `1 / (1 + r)`. Both of #181's scenarios pass: the 98.8% print
  isn't flagged, and caliper 1.015 with r = +0.015 is.
- The docstring, `recon/README.md`'s scale-agreement section and the `ScaleAgreement` description
  in `contracts/openapi.yaml` all say what each ratio means after the fix. Changing a description
  only isn't a D-031 contract round, but say so in the PR.

## Acceptance criteria

- A script loads a golden capture folder and runs VGGT on the pod.
- Writes per-frame camera poses, depth maps and a point cloud to disk.
- Wall-clock time recorded per run.
- Succeeds on at least one golden object.

## Notes and decisions

_Written while working. What you tried, what surprised you, what you chose and why._
_If a decision here governs later work, add it to `docs/decisions.md` with a number._

2026-09-25: Implementation written and unit-tested locally; **not yet run on the Studio** — the
acceptance criterion "succeeds on at least one golden object" is still open until someone runs it
on the shared Tesla T4 and records the real timings here (no numbers exist yet, so none are
quoted).

- `recon/vggt_runner.py` is the script. Everything except the model call is plain NumPy and
  unit-tested (`tests/test_vggt_runner.py`); PyTorch/VGGT are imported lazily inside
  `run_vggt_model`, so CI and the Mac bootstrap never need them.
- Output per run (`fixtures/data/recon_runs/<sample>/`, git-ignored): `poses.npz`, `depth.npz`,
  `points.ply`, `run.json` (per-stage timings, device, dtype, frame list). R-11 and R-12 should
  emit this same layout so R-04 can consume any backend behind the config flag (D-009).
- The point cloud is built by unprojecting the saved depth maps with the saved poses, not from
  VGGT's separate point-map head, so it is exactly what R-04/R-07 could rebuild from the files.
- dtype is chosen explicitly: fp16 on the T4 (compute capability 7.5, no fast bf16) and on Metal
  (D-011); bf16 only on capability >= 8.0.
- VGGT is not on PyPI, so `requirements-gpu.txt` pins an upstream commit. VGGT declares
  `numpy<2`, so `requirements.txt` now pins `numpy==1.26.4` (needed for the tests anyway).
- Poses and depth are in VGGT's arbitrary scale — not metric. R-04 fixes scale.
- Open risks to check on first real run: phone JPEG EXIF orientation is not applied by VGGT's
  loader; the model-weights licence for `facebook/VGGT-1B` should be checked before any
  non-course use; weights should live under a Teamspace Drive `HF_HOME` (D-036).

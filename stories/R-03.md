2026-09-27: Implementation is on `recon/R-03-camera-intrinsics`; real golden-capture
verification is still pending, so no measured calibration result is claimed yet.

- `recon/camera_intrinsics.py` consumes R-02's `board_poses.npz` corner arrays directly and
  reuses `recon.board_pose.make_board()`, so R-03 inherits D-034's corrected
  `setLegacyPattern(True)` board geometry instead of creating a second board definition.
- Session calibration uses every non-collinear frame with at least R-02's existing six-corner
  pose guard. A minimum of three usable views is an engineering solvability guard, not an
  accuracy threshold. R-02's EXIF-derived K is used only as OpenCV's initial guess.
- Primary output is one full-resolution stored-sensor K plus distortion coefficients.
  `intrinsics.json` reports overall and per-view reprojection RMS in pixels and explicitly says
  that this is self-consistency, not metric accuracy.
- If board calibration fails, the fallback reads R-01's `poses.npz` and `run.json`. VGGT K is
  defined in its resized-image coordinates, so R-03 rescales x and y independently using
  `processed_image_size_hw` before taking the median prediction across matching frames.
  The output records `source=vggt_fallback` and the calibration failure reason; fallback is
  never silent. VGGT supplies no lens-distortion estimate, so that fallback records zero
  distortion rather than pretending it was measured.
- Tests cover synthetic multi-view board calibration, the insufficient-view fallback path,
  full-resolution VGGT scaling, missing fallback artifacts, mixed sensor sizes, reprojection
  reporting, and overwrite refusal.

2026-09-27: Real golden-capture verification on Lightning, sample `s-04` (30 frames).
The R-02 handoff matched all 30 frame names; 29 frames had at least six detected ChArUco
corners, with 575 detected corners total at 5712×4284 stored-sensor resolution. R-03's primary
board-calibration path succeeded with `source=charuco_calibration`, used 29 board views, and
reported **1.197375 px reprojection RMS**. `fallback_reason` was null, so VGGT fallback was
not used in this real run. This RMS is only calibration self-consistency in pixels, not a
millimetre-accuracy or tolerance claim. The full test suite passed: 93 tests (2 pre-existing
`jsonschema.RefResolver` deprecation warnings).

## Why this exists

VLM capture supervision is one of the five generative-AI components the course grades and
that are never cut (AGENTS.md, D-017). It catches what the on-device gate can't: "whether
the object in frame is the right part, whether a hand is in the way, and whether the
'photograph' is a picture of a screen" (proposal §6.5). It was due in S2, and that sprint's
M2 gate ("a screen photo is rejected by the VLM") was missed. It passes the generative test:
run the same frame twice and the reply, including the hint, can differ.

## Acceptance criteria

- **Sampling and calls.** `recon/vlm_check.py` samples frame 0, every index with
  `i % 5 == 0`, and the final frame (`frame_count − 1`, known only at finish): 1 + ⌊(n−1)/5⌋
  calls, plus the final frame if it wasn't already sampled. Each call sends the frame (and,
  after frame 0, the reference frame 0) to a pinned Gemini Flash-Lite model, asks for
  structured output against a reply schema written in this story before coding (same part
  as the reference, hands occluding, photo of a screen, lighting adequate, a one-line
  coaching hint), and still validates the reply itself. The returned model version and token
  use are recorded.
- **Never blocks, never loses a result.** Calls run in an app-owned bounded executor, so an
  upload never waits on one; a test with a fake client that blocks on an event proves it.
  That's sound only because D-042 fixes one replica and one worker. Each result is its own
  atomic file, `<session>/vlm/frame_NNNN.json` (written to a temporary file, then replaced);
  `run_session` joins them after the pipeline, with a timeout, into `vlm_checks.json`.
  Nothing is written into `session.json`, which `run_session` overwrites.
- **Never a silent pass, and the key never leaks.** No key, an API error, a timeout, a
  blocked, empty or malformed reply, or a sampled frame with no result file at join time is
  recorded as `unchecked` with its reason. `GEMINI_API_KEY` is passed explicitly;
  `.env.example` documents it and how to load it locally; `scripts/deploy_recon.py` requires
  it and passes it in both the start call and the public-URL update; `redact()` masks any
  number of secrets as substrings; `deploy-recon.yml` and `recon/README.md`'s one-time setup
  add the secret; the service starts with no key; `google-genai` is pinned.
- **Recorded and checked by hand.** A decision records the model code chosen now (a stable
  snapshot, never a `-latest` alias), its announced retirement date, and the API tier and
  billing account, since supplier frames go to Google; `docs/manual.md` says so. A written
  manual check runs the real API on golden-set frames plus a photo of a screen and the
  wrong part, and records the replies, calls per session and token use.

## Tests

Unit tests with a fake client, written alongside the code (D-029): sampling indices, the
non-blocking executor, schema rejection, every `unchecked` path, the join timeout, and
`redact()` (including the existing `--env` test in `tests/test_deploy_recon.py`, which assumes
one `--env`). CI has no key and no network. The real-API run is the manual check above, because
it needs a key and makes paid calls.

## Notes and decisions

- Gating the verdict on these results is A-02, not here. Warn A-02: if `unchecked` blocks a
  Pass, a Gemini outage or a missing key turns every session into Rescan.
- Frame 0 establishes the reference, so its `same_part` is not applicable. If frame 0 is
  itself the wrong part, the "same part" checks still pass; catching that is CAD
  registration's job (M4). Named as a limit, not fixed here.
- `redact()` today swaps only a list element equal to the endpoint token, so a
  `GEMINI_API_KEY=<key>` element would print in full in the `Running:` line. Whether
  Lightning accepts a repeated `--env` is unverified, so the manual deploy check covers it.
- The key must never reach the phone app (D-042: "the phone app cannot hold a secret").
- The proposal's 19 h for VLM supervision includes per-frame checking and a local fallback,
  which it calls extensions; the sampled scope is its "Tier 1, ~10 h". This story plus A-02
  and A-11 is that scope.
- Use G-11's robustness set (screen photo, wrong part) for the manual check once it exists.
  No accuracy, cost or latency is claimed from it.

## Reply schema (written before implementation, 2026-10-26)

The model returns exactly these fields; local strict validation rejects extra fields,
coerced strings/numbers, blank/multiline hints and missing fields:

```json
{
  "same_part": null,
  "hands_occluding": false,
  "screen_photo": false,
  "lighting_adequate": true,
  "hint": "Keep the entire part visible."
}
```

`same_part` is null only for frame 0 (no reference); later samples require a boolean.
The hint is one nonblank line, at most 240 characters. These are observations/coaching,
not a Pass/Fail verdict. A-11 can carry this schema without changing A-01's upload response.
The persistence envelope adds frame index, `checked`/`unchecked`, a fixed reason code,
requested model, returned model version and token counts. A missing/error result never
contains made-up observation booleans.

Implementation plan: app-owned bounded executor; per-frame atomic files outside
`session.json`; idempotent sampling on upload and finish; one session-wide join deadline;
late completions cannot overwrite terminal timeout records. SDK requests have their own
finite timeout and no automatic retry. The live Gemini and Lightning checks remain
explicitly pending until an owner confirms API tier/billing and supplies the key securely.

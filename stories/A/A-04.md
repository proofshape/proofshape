## Why this exists

The proposal (§6.6): "A generative model then samples K plausible completions of the
geometry it did not [see], and different random seeds produce different surfaces. Where
those samples disagree is precisely where the system is guessing." Those samples feed the
disagreement map (A-05), which drives capture guidance and nothing else. Completed surface
"never touches the verdict" (D-005, D-006, issue #157).

## Acceptance criteria

- **The stage.** A-10's chosen model runs as a pipeline stage after R-10, timed under a
  `"completion"` entry in `stage_timings_s` (free-form, no contract change). It writes K
  samples to `artifacts/completion/sample_<k>.ply` and a `completion.json` (seeds, K, model,
  timing), in board-frame millimetres. K is a parameter; batch is the only path (D-002), so
  the default is the proposal's final-pass 8–10, with that reason stated.
- **The verdict mesh is untouched.** `mesh_uncertainty.glb` and `sigma.npz` stay
  byte-identical with the stage on or off, and the GLB served to the client is unchanged.
  `recon/provenance` gains `LABEL_INFERRED` and a source colour for later use, but no served
  file carries it yet.
- **Guidance can't break a reconstruction.** A completion failure is a warning, never a
  failed reconstruction, and an environment flag disables the stage. New dependencies go in
  `requirements-gpu.txt` and the image.

## Tests

Unit tests with a stub model, written alongside the code (D-029): the verdict outputs are
byte-identical, K sample files are written, the seed is passed through (same seed gives the same
output), and a model failure becomes a warning. CI has no GPU, so a written manual check runs
the real model on the golden set, shows that real seeds give different surfaces, and records the
stage timings.

## Notes and decisions

- Segmentation before completion, which the proposal makes mandatory, is already true:
  R-07's `fuse_run` segments every frame, so the mesh this stage reads is the part alone.
- Why the Inferred vertices stay out of the served mesh for now: `recon/next_view.py`
  raises on any label other than Observed or Unobserved, and treats the whole mesh as an
  occluder, where guessed surface must not block a view. Capture's colour mapping, legend
  and `docs/manual.md` change in whichever story first serves Inferred vertices; capture
  already reserves the display colour.
- The sprint plan's S4 Inspection bullet put "label completed surface Inferred" in the
  inspection lane. Defining the label moves here, where the surface is produced; excluding
  it from deviation stays with I-06/I-07.
- Not here: the disagreement map (A-05), and the contract's must-be-false wording for
  `inferred` regions (it rides on I-07's D-031 request).

- **From A-10 (D-057), 2026-11-02:** the model is LaS-Comp, pinned there. Facts that change
  this story:
  - **Input and output.** Input is a PLY point cloud plus one photo, normalised to a unit cube and
    mapped back afterwards, so coordinates stay in millimetres. It expects z up, while the board
    frame's z points into the board, so turn it 180° about x first. Output is a mesh in the input's
    coordinates; sample it to points for `sample_<k>.ply`.
  - **Cost.** About 5 min and 11.3 GB per sample on a T4, plus 48 s to load. That makes the default
    K of 8–10 above 40–50 min, so set K from a measured time budget instead.
  - **Environment.** It needs Python 3.10 and torch 2.4.0+cu121, so it runs as a separate process,
    not in the service's Python ≥3.11 interpreter. The heavy CUDA dependencies (spconv, kaolin,
    pytorch3d, xformers) belong in that environment, not `requirements-gpu.txt`. Install LaS-Comp
    at build time: its repository has no LICENSE file.
  - **Setup.** The TRELLIS `pipeline.json` needs a `sparse_structure_encoder` entry (see A-10).
  - **Correction to the note above:** the served model isn't "the part alone" yet. On s-04 it still
    had a thin board skin, 3–5 mm above the board, across the whole area. A-10 isolated the part
    by height and clustering, so this stage needs the same step, or a fix upstream first.
  - `sigma.npz` in the criteria is `sigma_mm.npz` in the code (`recon/uncertainty.py`).
  - The contract wording for `inferred` regions now rides on A-11's D-031 request (D-056), not
    I-07's.

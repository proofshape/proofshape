## Why this exists

"The hint reaches the user in the capture UI, so a supplier is told 'your hand is covering
the left flange' rather than being silently rejected" (proposal §6.5). The frozen contract's
upload response has no field for it, and there is no endpoint the app polls during capture,
so this needs a contract change, which needs both other members' approval at a sprint
boundary (D-031).

## Acceptance criteria

- **One D-031 request**, approved by both other members and merged at a sprint boundary
  (Oct 30 or Nov 13): an optional field on `UploadFrameResult` carrying the latest completed
  VLM result and its hint, plus a dedicated malformed-upload error code in place of the
  `vlm_veto` and `frame_rejected_exposure` codes it borrows today (R-14's recorded debt).
- **Capture shows the hint** during the capture loop without blocking capture, and says
  plainly that it describes an earlier frame: the check is asynchronous, so the hint
  arrives one or more sampled frames late.
- **Tests and docs:** contract tests, an example response under `contracts/examples/`, capture
  unit tests, and `docs/manual.md`'s upload-error and capture sections updated.

## Tests

Contract tests and capture unit tests, written alongside the change (D-029).

## Notes and decisions

- No dependency on A-01 on purpose: the field is designed and tested against the mock
  service first, so the D-031 request can make a sprint boundary. The field carries A-01's
  reply schema, agreed with A-01's owner before either merges.
- The malformed-upload code isn't generative AI; it rides along because it needs the same
  D-031 approval. Its share of the hours is non-generative.
- Merges after C-13, which edits the same capture files.

**As built (2026-10-29), recorded in D-056:**
- The field is `vlm_feedback`: the newest *checked* result's `frame_index`, `hint` and four
  checks, read from disk after the upload is queued (`vlm_check.latest_checked`). It is absent
  until a check finishes; `same_part` is present and `null` for frame 0. Model, tokens and
  `unchecked` reasons stay server-side. A-01 had already merged (#207), so the shape follows
  its `FrameObservation`; @mbj1994's OK on it, as A-01's owner, is asked for in the review.
- Two codes, not one: `malformed_request` (R-14's debt) and `internal_error` (#186's contract
  half, which `stories/README.md` assigned here). The same change widens
  `contributes_to_verdict`'s wording to every non-`observed` provenance, which R-29 noted
  needed D-031. Neither code is generative AI; the completion record notes their share.
- Capture shows "Tip (from frame N): ..." under the capture status, as text, kept until a newer
  tip arrives. The stub serves it with `PROOFSHAPE_STUB_VLM_FEEDBACK=1 npm run dev`.
- `pydantic>=2.12` is pinned: `Field(exclude_if=...)` drops an empty field while keeping
  `same_part: null`, which a route-level `exclude_none` would have dropped too.
- The service tests now clear `GEMINI_API_KEY`, so a developer's real key can't turn them into
  paid API calls.

## Why this exists

The capture agent is built, tested and Done, but no real session reaches it (#406):

- A-07's loop (`recon/agent_loop.run_agent_turn`) and A-13's pinned model
  (`recon/agent_model.GeminiAgentCaller`) run only from tests and `scripts/check_agent_model.py`.
- `recon/service.py` has no `agent-message` route.
- C-22's assistant panel calls `GET /v1/sessions/{id}/agent-message` (`capture/src/api.ts`). It
  stays hidden against the real service because the route doesn't exist.

A-07 named the missing piece itself: "a new field or route, the same shape as A-11's hint
addition. This is a D-031 round." No story took it on. The capture agent is one of the
generative-AI components the sprint plan says are never cut (§10). Without this story, the
final report has to describe it as built but not served.

**This is required scope, not an option.** The capture agent is a generative-AI component, and
those are never cut (`AGENTS.md`, D-017). #406's second option, recording the agent as cut for v1,
is withdrawn for that reason. The team decides how a turn runs (below), the agent-against-policy
comparison and the Dec 2 freeze exception, not whether the agent is served.

## Acceptance criteria

- **A D-031 contract round.** `contracts/openapi.yaml` gains the `agent-message` operation, with
  the result shape C-22 already reads (`finished`, `fallback_reason`, `message`). The contract
  goes up a minor version from 1.8.0, with an example for each response. Both other members
  approve, and it merges at a sprint boundary. Since M5's feature freeze has passed, the Dec 2
  call records a named exception for it.
- **The service runs A-07's loop for a real session.** It uses A-13's pinned model when a Gemini
  key is configured, and A-08's deterministic policy when there's no key, or on error, timeout or
  loop. The session always completes, and the route never waits on the model beyond A-07's
  per-call bound. Tests run a mock model through the real in-process app (`create_app`) and cover:
  - a model reply;
  - each of the three fallback reasons;
  - no key configured;
  - an unknown session.
- **C-22's panel shows against the real service.** Its hidden-until-the-route-answers rule then
  lights it up with no change to the panel. `docs/manual.md` §4 says the agent is served. One
  real iPhone session with the key set records what the agent said, as a transcript, not judged.

## Tests

The route, the loop's wiring and the fallback paths are unit-tested through `create_app` with a
mock model caller, written with the code. The new contract examples are checked by
`tests/test_contract.py`, which reads every file under `contracts/examples/`. The iPhone session is a written check, because it needs a real phone and a live
model call.

## Notes and decisions

- **Written up by P-37** (2026-11-20), from #406. The fold check ran on `main` at `5a86da4`:
  `git grep agent-message -- stories docs` finds only C-22, the manual and a progress-log line.
  A-07, A-13 and C-22 are Done, and none of them owns the route.
- **Open design question, for the owner at claim. When does a turn run?** `run_agent_turn` can
  call `finish_session` and schedule reconstruction, so it has side effects. C-22's client polls
  with `GET`, so running a turn on each `GET` would put those side effects on a `GET`. There are
  two ways round it:
  - **(a)** run a turn after each accepted frame upload, store the latest result on the session,
    and have `GET` return it;
  - **(b)** change the client to `POST`.

  Option (a) keeps C-22 unchanged. A related question is whether the agent may finish a live
  session at all, when today the supplier taps Finish. The manual (§4) says the model can't
  finish while orbit slots remain uncovered.
- **The agent against the deterministic policy.** S6 asks "does the agent actually beat the
  deterministic policy?", and the proposal puts agent evaluation in the inspection lane (§13). A-08
  calls itself that baseline, but no story runs the comparison, and it can't run on real sessions
  until this route exists. The team picks one of three at the Dec 2 call:
  - inside this story, as a fourth criterion;
  - a story of its own;
  - recorded as not measured, in the final report (P-38).
- **Timing.** D-031 merges only at a sprint boundary, and the next one is Dec 2. S7 (Dec 3–4) is
  the code freeze, with "no behavior-changing commits", so this has to merge at the Dec 2
  boundary. If it misses, the final report states that as a shortfall against D-017, not as a
  cut, and the team flags it (`AGENTS.md`). The tests and the route can be built before then.
- **X-04** runs the whole system on the iPhone. If this story merges first, X-04's session
  exercises the agent too.
- **Estimate basis:** A-11 has the same shape, a D-031 contract change plus the capture message,
  and took 7 h actual (est 4). C-22's panel already exists here, so 6 h.

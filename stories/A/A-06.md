## Why this exists

The capture agent (proposal §6.7) is a tool-calling loop over five tools, "each already
exists and is deterministic": `score_next_view`, `check_frame`, `vlm_inspect`,
`coverage_report`, `finish_session`. The agent "does not compute geometry"; the tools do.
Defining them first, with no language model involved, gives both the agent (A-07) and its
deterministic fallback (A-08) the same footing. The agent is the largest generative-AI item
(the proposal's 30 h) and nothing has started it.

## Acceptance criteria

- **Where the tools run is decided first.** The agent runs on the server, because the phone
  can't hold the model's API key (D-042). But two tools' sources live on the phone today:
  the frame gate (`capture/src/frame_gate.ts`) and orbit coverage (`capture/src/orbit.ts`).
  How their results reach the server (reported with each upload, which is a contract change
  under D-031, or recomputed server-side) is written down and recorded as a decision before
  any code.
- **Each of the five tools** has a typed input and output schema and a deterministic
  implementation that wraps code that exists: `score_next_view` over
  `recon.next_view.score_next_views`, `check_frame` over the gate result, `vlm_inspect` over
  A-01's latest result, `coverage_report` over orbit coverage and the provenance labels, and
  `finish_session` over the existing endpoint's logic. A tool whose source isn't built yet
  (`vlm_inspect` before A-01) returns an explicit `unavailable`, never a guess.
- **No language model in this story.** Same input gives the same output for every tool, and the
  schemas are what A-07 hands the model and what A-08 calls directly.

## Tests

Unit tests in `tests/test_agent_tools.py`, written alongside the code (D-029): `compute_coverage`
cross-checked against `capture/src/orbit.test.ts`'s own known cases (first-slot coverage, just-
outside-tolerance, full coverage, the azimuth-exempt straight-down slot, the nearest-single-slot
regression); `score_next_view`/`coverage_report` before and after a reconstruction exists;
`check_frame`/`vlm_inspect`'s `unavailable` paths and determinism; `finish_session`'s five
outcomes (not found, too few frames, already finished via the early check, already finished via
a genuine `mark_finished` race, success schedules reconstruction). A regression test in
`tests/test_reconstruction_service.py` covers `mark_finished` raising the typed
`SessionAlreadyFinishedError` rather than a plain `RuntimeError` on a losing race. The rest of
that file's existing tests pass unmodified, confirming the `finish_session` extraction didn't
change behaviour.

## Notes and decisions

- The tools are deterministic; the generative part is the agent that chooses between them
  (A-07). That is what passes the "run it twice" test, not these.
- `score_next_view` reads a mesh, and batch is the only capture path (D-002), so it can only
  run after a reconstruction. A-08 decides what that means for the policy.
- If the decision in the first criterion needs a contract change, the D-031 request is named
  in this story and timed for a sprint boundary, alongside A-11's if possible.

2026-10-23: Implementation. The first criterion's decision is **D-054**: orbit coverage is
recomputed server-side from each accepted frame's already-persisted gyro reading (no contract
change); `check_frame` is `unavailable` for every call, since the gate's actual result never
reaches the server and this story doesn't add a D-031 contract field to carry it.

- **`recon/agent_tools.py`** (new, in the `recon/` lane — matching A-01's own
  `recon/vlm_check.py` precedent, since there is no separate `agent/` directory): all five
  tools, each returning a `ToolResult(available, reason, data)`. `score_next_view` and
  `coverage_report` both go `unavailable`/orbit-only respectively until
  `record["reconstruction"]["status"] == "complete"`; `vlm_inspect` and `check_frame` are
  unconditionally `unavailable` — A-01 doesn't exist yet, and the gate result isn't reported.
- **`recon/service.py`**: the `finish_session` route is now a thin adapter over
  `agent_tools.finish_session`, which takes the store and a `schedule_reconstruction` callback
  explicitly (the route passes `background_tasks.add_task`; a test passes `list.append`) — one
  shared implementation instead of the route and the tool each carrying their own copy of the
  same validation.
- `coverage_report` combines orbit coverage with `score_next_view`'s
  `under_observed_visible_count` only once a reconstruction exists — pre-reconstruction it
  reports orbit coverage alone, since there is nothing else to combine yet.
- Decision number checked properly: every branch on `origin` was fetched; nothing past D-053
  existed anywhere, so D-054 was free.

2026-10-24: @mbj1994's review of PR #176 caught two real issues, both fixed in the same PR:

- **`check_frame` didn't satisfy its own acceptance criterion honestly.** The first cut had it
  answer `upload_frame`'s server-side accept/reject outcome instead of the gate result the
  criteria actually name — a real signal, but a different question, which made the criterion
  look satisfied while a different tool was actually built under the same name. Fixed by
  reverting to an honest `unavailable`, the same pattern `vlm_inspect` already uses for A-01 not
  existing: this story's acceptance criterion for `check_frame` is **not fully met** today, by
  name, not silently — a real gate-backed `check_frame` is future work once that telemetry
  exists (a D-031 request this story deliberately doesn't spend). The `last_frame_event`
  plumbing (a `SessionStore` addition, two call sites in `upload_frame`) was removed entirely
  rather than left as unused infrastructure. D-054 rewritten to match, recording the rejected
  alternative and why.
- **A real concurrency bug in code this story touched, predating it.** `SessionStore.
  mark_finished` raised a plain `RuntimeError("session_already_finished")` on a losing race, but
  both the original route and `agent_tools.finish_session` only ever caught the typed
  `SessionAlreadyFinishedError` — so a genuine concurrent race would have escaped as an
  uncaught 500 instead of the structured 409 every other race path already returns. The
  existing regression test for this path (`test_finish_race_returns_409_not_500`) never caught
  it because it monkeypatches `mark_finished` to raise the *correct* exception directly, rather
  than exercising the real method. Fixed by raising `SessionAlreadyFinishedError` (already a
  `RuntimeError` subclass, so nothing catching broadly breaks) instead of the plain class, with
  two new regression tests: one driving the real `mark_finished` twice to confirm the typed
  exception, one driving `agent_tools.finish_session` through a `mark_finished`-raises path
  distinct from the early status-check path the existing "already finished" test actually hits.

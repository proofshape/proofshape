## Why this exists

The capture agent (proposal §6.7) is a tool-calling loop over five tools, "each already
exists and is deterministic": `score_next_view`, `check_frame`, `vlm_inspect`,
`coverage_report`, `finish_session`. The agent "does not compute geometry"; the tools do.
Defining them first, with no language model involved, gives both the agent (A-07) and its
deterministic fallback (A-08) the same footing. The agent is the largest generative-AI item
(the proposal's 30 h) and nothing has started it.

## Acceptance criteria

- **Where the tools run is decided first.** The agent runs on the server, because the phone
  can't hold the model's API key (D-042). But two tools' sources live on the phone today:
  the frame gate (`capture/src/frame_gate.ts`) and orbit coverage (`capture/src/orbit.ts`).
  How their results reach the server (reported with each upload, which is a contract change
  under D-031, or recomputed server-side) is written down and recorded as a decision before
  any code.
- **Each of the five tools** has a typed input and output schema and a deterministic
  implementation that wraps code that exists: `score_next_view` over
  `recon.next_view.score_next_views`, `check_frame` over the gate result, `vlm_inspect` over
  A-01's latest result, `coverage_report` over orbit coverage and the provenance labels, and
  `finish_session` over the existing endpoint's logic. A tool whose source isn't built yet
  (`vlm_inspect` before A-01) returns an explicit `unavailable`, never a guess.
- **No language model in this story.** Same input gives the same output for every tool, and the
  schemas are what A-07 hands the model and what A-08 calls directly.

## Tests

Unit tests written alongside the code (D-029): every tool is deterministic, rejects input that
doesn't match its schema, and returns `unavailable` when its source is missing.

## Notes and decisions

- The tools are deterministic; the generative part is the agent that chooses between them
  (A-07). That is what passes the "run it twice" test, not these.
- `score_next_view` reads a mesh, and batch is the only capture path (D-002), so it can only
  run after a reconstruction. A-08 decides what that means for the policy.
- If the decision in the first criterion needs a contract change, the D-031 request is named
  in this story and timed for a sprint boundary, alongside A-11's if possible.

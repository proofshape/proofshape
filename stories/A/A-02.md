## Why this exists

Proposal §6.5: the VLM is first-class in the sense that it can veto a Pass. "No session reaches
Pass until every sampled frame has passed. A failure downgrades the session to Rescan and the
report names the reason." A-01 built the sampling and recording of observations
(`<session>/vlm_checks.json`) but deliberately stopped there: "Gating the verdict on these
results is A-02, not here." `recon/README.md` names this story directly: "A-11 will expose hints
in the phone UI; A-02 will define policy. If A-02 makes `unchecked` block a Pass, an outage or
missing key will turn affected sessions into Rescan; that choice is not made here." The contract
already carries a `vlm_veto` error code, but only on loan: `docs/manual.md`'s error table says
"Today this means a malformed upload, not a semantic check — A-01 records asynchronous
observations, but A-02's veto policy is not built." A-11's own contract-change request frees the
code from that borrowed use.

## Acceptance criteria

- The policy is a deterministic function over A-01's already-recorded `vlm_checks.json` (the
  same inputs give the same veto decision every time), distinct from A-01's own generative calls,
  which is what satisfies AGENTS.md's "run it twice" test for this component.
- The policy states, as a recorded decision, how an `unchecked` result (outage, missing key,
  timeout, a blocked or malformed reply) is treated — whether it blocks a Pass or is handled more
  leniently. This is the open question `recon/README.md` and A-01 both explicitly left for this
  story; do not invent the answer here without recording it as a decision.
- A failing semantic check (wrong part, hands occluding the view, a photo of a screen) on any
  sampled frame downgrades the session to Rescan, per proposal §6.5, with `reason_codes` naming
  the failure for the report to explain.
- The `vlm_veto` error code's real semantic meaning only takes effect once A-11 has freed it from
  its current malformed-upload borrow — this story should not ship in a way that conflicts with
  A-11's own D-031 contract request.

## Tests

Written alongside the policy: a synthetic `vlm_checks.json` with every sampled frame passing →
no veto; one failing frame → Rescan with the right reason code; an `unchecked` result exercised
against whichever policy this story decides on, pinning that choice rather than leaving it
implicit.

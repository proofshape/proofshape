## Why this exists

`docs/manual.md` §8.3: "Planned: an LLM writes the narrative summary (A-09)." Proposal §7.5:
"Templated text; an LLM narrative is a Tier 3 add-on," and §8.3 (via §9's component table):
"LLM narrative for the report, generated from the structured result, never from the images." C-15
already reserves this story's landing spot and does the non-LLM half itself: "No LLM. A-09's
narrative gets a marked slot and nothing more," while separately showing "every reason code in
plain language" through its own templated, non-LLM lookup. A-09 is the higher-level free-text
paragraph the proposal calls a "narrative," not that lookup table.

**A real, unresolved conflict, stated plainly rather than settled here:** proposal §7.5/§9 twice
call this story Tier 3, and `docs/sprint-plan.md` §10's cut order ends "...interactive mode
(batch stays) → report polish → LLM report narrative" — the single most cuttable item in the
whole project. But AGENTS.md/D-017 name the report narrative as one of five generative-AI
components that are "never cut" and "carry the same protection as Tier 1." C-15's own notes
already flag this exact contradiction: "P-30 raises that conflict for the team; this story
doesn't settle it." This story inherits the same unresolved tension and states it plainly rather
than picking a side.

## Acceptance criteria

- Generates a prose paragraph from `VerdictResult` fields only (`verdict`, `regions`,
  `reason_codes`, `orientation_ambiguous`, `declared_at`) — never from capture photographs or the
  3D model directly, per proposal §7.5/§8.3's explicit constraint.
- Lands exactly in C-15's already-reserved slot; does not duplicate or replace C-15's own
  templated reason-code-to-plain-language table.
- States no unmeasured tolerance, accuracy or σ figure (D-003 lane-wide rule), matching C-15's
  own criteria for the rest of the report page.
- Model choice and pin are recorded as a decision, following A-01's precedent (a stable snapshot,
  never `-latest`), since the proposal names no specific model for this component.

## Tests

Written alongside the generator: a handful of example `VerdictResult` fixtures (Pass, Fail,
Rescan, Unverifiable) each producing a paragraph that mentions only facts present in the input,
checked for no invented tolerance/accuracy language.

## Notes and decisions

- **The Tier-1-vs-Tier-3/cut-list contradiction** above is explicitly unresolved, as C-15/P-30
  already recorded; whoever claims this story should raise it with the team rather than resolve
  it unilaterally inside the acceptance criteria.
- **No `reason_codes` vocabulary exists yet** (I-07 defines the enum this story would narrate
  specifically). Until I-07 lands, this story can only build against the generic `verdict`/
  `regions`/`orientation_ambiguous` fields that already exist in the frozen contract.
- Whether this story should degrade to a templated fallback if the LLM call fails (mirroring
  A-08's "the session always completes" pattern for the agent) is not decided anywhere; a real
  design question for whoever claims it.

## Why this exists

paragraph the proposal calls a "narrative," not that lookup table.

**A real, unresolved conflict, stated plainly rather than settled here:** proposal §7.5/§9 twice
call this story Tier 3, and `docs/sprint-plan.md` §10's cut order ends "...interactive mode
(batch stays) → report polish → LLM report narrative" — the single most cuttable item in the
whole project. But AGENTS.md/D-017 name the report narrative as one of five generative-AI
components that are "never cut" and "carry the same protection as Tier 1." C-15's own notes
already flag this exact contradiction: "P-30 raises that conflict for the team; this story
doesn't settle it." This story inherits the same unresolved tension and states it plainly rather
than picking a side.

## Acceptance criteria

- Generates a prose paragraph from `VerdictResult` fields only (`verdict`, `regions`,
  `reason_codes`, `orientation_ambiguous`, `declared_at`) — never from capture photographs or the
  3D model directly, per proposal §7.5/§8.3's explicit constraint.
- Lands exactly in C-15's already-reserved slot; does not duplicate or replace C-15's own
  templated reason-code-to-plain-language table.
- States no unmeasured tolerance, accuracy or σ figure (D-003 lane-wide rule), matching C-15's
  own criteria for the rest of the report page.
- Model choice and pin are recorded as a decision, following A-01's precedent (a stable snapshot,
  never `-latest`), since the proposal names no specific model for this component.

## Tests

Written alongside the generator: a handful of example `VerdictResult` fixtures (Pass, Fail,
Rescan, Unverifiable) each producing a paragraph that mentions only facts present in the input,
checked for no invented tolerance/accuracy language.

  earlier note assumed): `inspect/inspection/verdict.py` defines
  `f"{name}_not_seen"`/`f"{name}_deviation_out_of_spec"`/`f"{name}_high_sigma"`/

  (`intake_tolerance_below_k_sigma_floor:hole_A`), copied from I-10's own
  `tests/test_verdict_endpoint.py`, not hand-invented.
- **Split into two pull requests, this one being the first.** Exploring the contract found that
  serving a narrative anywhere needs a `contracts/openapi.yaml` change — `VerdictResult`'s only
  `x-proofshape-extends-at` marker (D-032) is scoped to the tolerance table/`k`/`σ_floor`, not
  narrative text — which is a D-031 round (both other members' approval, merged only at a sprint
  boundary; next one is Dec 2, we're mid-sprint). Rather than fold a contract change into the same
  PR as the generator, this PR builds and tests **only the generator**
  (`recon/report_narrative.py`), with no contract, service or frontend change. **A second PR**
  will add the `narrative` field (or equivalent), `recon.service` wiring, and
  `capture/src/report.ts`'s render, raised as its own explicit D-031 request to
  `@TabeenRaoof`/`@mbj1994` — see D-081. **Because of the split, this story's acceptance criteria
  are not yet fully met** ("lands exactly in C-15's reserved slot" needs PR 2), so `State` stays
  `Claimed` here rather than `Done`.
- **Fallback decided:** on any LLM failure (error, timeout, blocked/incomplete/empty reply, or a
  reply that states a figure or outcome not licensed by the input), the generator falls back to
  a fully deterministic templated paragraph built from the same fields, distinguished from a
  real model narrative only by `NarrativeResult.source`/`reason` — the "session always
  completes" shape A-08 established, adapted for a single call rather than a tool loop.
- **Design settled through four review rounds (PR #387) — the final shape, not the history
  of getting there:**
  - **The verdict statement is always deterministic.** `generate_narrative` always prepends
    `template_narrative`'s own output (the real verdict, in code) before considering anything
    from the model; the model is asked only for a short *explanation* of why, appended after it.
    This was round 3's redesign (@TabeenRaoof): rounds 1-2 tried to ban words/phrases naming a
    *different* verdict than the one given, but that list never converges against free text —
    "the part meets its specification", "no defects were found", "does not conform" and a dozen
    other paraphrases all state an outcome without tripping a per-direction list. Making the
    verdict itself un-writable by the model, and banning the entire outcome/conformity
    vocabulary outright in *either* direction (`_invalid_explanation_reason`/`_BANNED_WORD_RE`),
    turns four never-finished lists into one that at least stops growing with the direction.
  - **The figure check** (decimal/length-unit figures not already in a region's own
    `deviation_mm`, at the precision the input actually carries — never a rounded `.0f`, which
    let a real 1.8 mm deviation be restated as an invented "2 mm") is unchanged by that redesign
    and still catches spelled-out units, unitless decimals, and invented percentages.
  - **Word-boundary matching**, not substring: `\bship\b` doesn't match inside "relationship",
    `\bpass\b` doesn't match inside "passage" (round 3, @TabeenRaoof) — explicit inflections per
    word rather than a stem wildcard, since a wildcard suffix after "pass"/"ship" would have
    reintroduced exactly that bug.
  - **Groundedness, round 4 (@mbj1994):** a bare, context-free approval ("Everything checks
    out.") carries no banned word and no figure, so the vocabulary ban alone never catches it.
    `_is_grounded` requires an explanation to cite something the input actually gave — a region's
    own name, or a reason code — rejecting it regardless of vocabulary otherwise. A verdict with
    nothing at all to cite trusts no explanation, ever. A few more approval idioms ("checks out",
    "all good", "no concerns", "nothing wrong", "as expected", "in order", "all clear") are
    banned outright too.
  - **Region-name and reason-code injection into the *deterministic* path, round 4
    (@mbj1994):** `regions[].name` is buyer-supplied, unvalidated text (R-34) that
    `template_narrative` — the fully deterministic fallback, not just the LLM path — inserted
    verbatim for a contributing region. A name crafted to read as an outcome reached the report
    even when the model was never called. `_sanitize_for_narrative` now applies the same
    figure/outcome checks to every region name and reason code before either path displays it,
    replacing an unsafe one with a positional label (`region 1`, `reason 1`, ...) rather than
    ever failing to render. **A known, narrow residual gap, stated rather than hidden:** I-07/I-10
    build a reason code as `f"{name}_not_seen"` with no separating space, which removes the one
    word boundary between a name's *last* word and the fixed suffix — a single-word malicious
    name positioned exactly there, with no other banned word anywhere else in the string, could
    still slip through. Documented in the module docstring, not silently left for someone to
    rediscover.
  - Every probe row from all four review rounds is now a named regression test in
    `tests/test_report_narrative.py` (62 tests total), including the injected-`regions[].name`
    case (both the LLM-echo and the pure-deterministic-template versions), the "legitimate word,
    wrong place" case ("relationship", "passage"), and a realistic injected reason code
    (`nothing wrong here_not_seen`, mirroring the real `f"{name}_not_seen"` shape rather than an
    artificial all-underscore string that would dodge word-boundary matching for the wrong
    reason).
- **Live model check:** `scripts/check_report_narrative.py` exists (mirrors
  `scripts/check_agent_model.py`'s shape) but was not run against the real API in this session —
  the sandboxed environment's permission layer declined the outbound call with a key present in
  `.env`. Whoever next has a terminal without that restriction should run it and record the real
  result here before PR 2, per A-13's own precedent.

## Acceptance criteria

- Largest connected component kept, small holes filled, decimated to a target triangle count.
- Exports a GLB that loads in a browser.
- File size under a stated limit.

## Notes and decisions

_Written while working. What you tried, what surprised you, what you chose and why._
_If a decision here governs later work, add it to `docs/decisions.md` with a number._

2026-09-30: Implemented in `recon/mesh_cleanup.py` (`keep_largest_connected_component`,
`find_boundary_loops`, `fill_small_holes`, `decimate_mesh`, `write_glb`/`read_glb`, `cleanup_run`,
plus a CLI), consuming R-07's `mesh.ply` directly via `tsdf_fusion.read_mesh_ply`. Order follows
the acceptance criteria's own wording: keep largest component → fill small holes → decimate →
export.

Unlike R-06/R-07, none of this story's criteria say "for every golden object" or otherwise need
real captured photos — mesh cleanup and GLB export operate purely on a mesh, so this closes
end-to-end in one session with synthetic-data tests, no follow-up story needed for real data.

**No measured numbers exist for "a target triangle count," "small holes," or "a stated [file
size] limit"** — same situation R-06/R-07 hit. Configurable defaults, documented as assumptions,
not measured figures: `DEFAULT_TARGET_TRIANGLE_COUNT = 50,000` and
`DEFAULT_MAX_FILE_SIZE_BYTES = 15 MiB` (common web-asset budgets), `DEFAULT_MAX_HOLE_LOOP_LENGTH
= 8` edges. A boundary loop longer than that is left open on purpose rather than closed: a large
opening more likely means a genuinely unreconstructed region than a small gap, and silently
closing it would assert geometry nothing ever observed — the same spirit as the hard rule, even
though this story runs before R-09's per-vertex provenance exists to label anything Observed/
Unobserved.

**Dependency decision:** `fast-simplification` (real quadric decimation, takes a target triangle
count directly) and `pygltflib` (real GLB read/write) are both core to this story's primary
acceptance criteria — not a fallback path like R-07's Open3D/Poisson — so both are real
`requirements.txt`/CI dependencies rather than lazily imported and untested. `scipy` (used for
`keep_largest_connected_component`'s connected-components graph) was already installed
transitively via `scikit-image`; pinned explicitly now that it's imported directly.

**"Loads in a browser" is checked by round-trip, not an actual browser session.** `read_glb`
parses back what `write_glb` wrote via the same `pygltflib` library — a genuinely malformed GLB
won't round-trip either, so this is a real structural check, not a rubber stamp — but it isn't a
literal browser loading the file. Since this doesn't need GPU or golden-capture data (unlike
R-17/R-18's gap), it doesn't warrant its own follow-up story: whoever wants the literal criterion
confirmed can drag an exported `.glb` into a public viewer in a few seconds.

`find_boundary_loops` assumes a manifold, consistently-wound mesh with simple (non-branching)
boundary loops — true of this pipeline's own marching-cubes output — and skips (rather than
guesses at) a loop that can't be walked back to its start under that assumption.

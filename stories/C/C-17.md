## Why this exists

The proposal's board carries a "per-PO QR code and an orientation arrow in the margin" (§6.1), so
a printed sheet belongs to one order. The buyer's last setup step generates that sheet (§3, manual
§4 step 4). Today every order prints the same `fixtures/charuco_board.pdf`, with nothing on it to
say which order it is. D-034 left the code and the arrow "Not yet decided". I-05's placement
note ("hole A toward the sheet's arrow") assumes the arrow exists.

## Acceptance criteria

- **"Print the sheet" on the buyer page** produces a PDF for that order.
  - It contains `fixtures/charuco_board.pdf`'s page, embedded unchanged at 1:1: never redrawn or
    regenerated (manual §3.1, D-034). The copy the browser loads is checked against the
    fixture's sha256.
  - Outside the pattern, clear of the paper's edge, it adds the order code as text, a QR code
    encoding the order code, an orientation arrow along a named board axis, and "Print at Scale:
    100%".
- **A raster check in Python.** `tests/test_order_sheet.py`, built on `tests/test_board_pose.py`'s
  helpers, renders a committed sample sheet for `PO-48213-A` and checks:
  - all 35 board corners are found;
  - the corners sit at a 20 mm pitch, measured from the PDF's own units;
  - only the board's own marker IDs are found, none produced by the QR code;
  - the QR code decodes to the order code (`cv2.QRCodeDetector`).
- **The sample is the generator's real output.** A vitest regenerates it with fixed PDF dates and
  compares bytes, so the Python check covers the generator the buyer page runs.
- **Recorded as a decision when built:** the layout D-034 left open, meaning positions, the
  arrow's axis and the paper size.

## Tests

The raster check and the byte comparison above, plus unit tests for the layout maths: every added
mark stays outside the pattern and inside the printable area. One manual check: print one sheet at
100% and caliper two squares (manual §3.3), because a printer's real scaling can't be tested in CI.
Record it in C-13's format.

## Notes and decisions

- **Where it's generated: in the browser, in `capture/`.**
  - The order code is already on the buyer page.
  - It needs no new endpoint, so no D-031 round.
  - It works from a static host while the GPU service is stopped.
  - The cost is two pinned npm dependencies, a PDF writer and a QR encoder.
  - The alternative is Python, with pypdfium2 and OpenCV's QR encoder, both already pinned. It would
    need a sheet route in the contract and the service running whenever someone prints a sheet.
- **The page size has to be decided.** The committed PDF's page is 200 × 150 mm, not A4 or Letter
  (measured 2026-11-09: 566.9 × 425.2 pt). Two options:
  - draw on its own narrow margins, 20 mm and 15 mm round the 160 × 120 mm pattern;
  - place it unchanged on a full A4 or Letter page (recommended).

  Either way, keep a clean margin between the pattern and the paper's edge. The paper's outline
  is one of the three scale checks (manual §3.2, D-034).
- **Out of scope:**
  - reading the QR code at capture, which is session integrity (proposal §8.2, Tier 3, 3rd on the
    cut list);
  - any check by the service that the sheet matches the session.
- **Freeze and cut list.** S5 work in the sprint plan ("board PDF with PO code"), filed
  2026-11-09, four days before M5's feature freeze. If the Nov 13 call cuts part of it, the QR
  code goes first, being session integrity. The printed code and the arrow stay, because the
  placement note refers to the arrow.
- **Open question:** encode only the order code (recommended), or the whole capture link, which
  goes stale whenever the host changes.
- **Fold check** (2026-11-09). No story in flight owns this.
  - No branch has a sheet generator, a QR encoder or detector, or an arrow (searched every
    origin branch's `capture/`, `recon/`, `scripts/` and `.github/`).
  - No earlier story mentions a QR code; only D-034, the proposal and the manual do, as a plan.

  So it's a new story.
- **Estimate basis:** `tests/test_board_pose.py` already renders and checks the board PDF. This
  adds a generator and one test file.

## Why this exists

Nothing in `capture/` can display a GLB yet, and three.js (named in the pinned stack, §9) is not
even a dependency. The proposal's own description of what the user sees — "a 3D model appears in
the browser seconds after the last frame" — has nothing behind it client-side. C-10 gives the
page a `glb_url` to point at; this story is what renders it.

## Acceptance criteria

- Given a `glb_url` from C-10's completed result, three.js loads and renders it in a canvas sized
  to the viewport, with touch-drag orbit and pinch zoom.
- A "download GLB" control using the same `glb_url`, so the raw model stays retrievable even if
  in-browser rendering fails for some reason.
- A `failed` status, or a `complete` status with no `glb_url`, shows a specific message in place
  of a blank or broken viewer — no silent failure, per `AGENTS.md`'s rule.

## Tests

The loader is invoked with the right URL, and the fallback message renders without ever calling
the loader on a failed/missing-URL result — both testable against a mocked `GLTFLoader`, no WebGL
needed for either.

Manual check — 2026-10-14, real iPhone, Safari bundled with iOS 26.5.2 (standalone Safari
build not separately recorded). Opened the HTTPS Lightning viewer-demo route, confirmed the GLB
rendered, orbited with one finger, pinch-zoomed with two fingers, and tapped Download GLB. Result:
render pass; one-finger orbit pass; pinch zoom pass; download pass. During orbit the canned model
briefly disappears from back-facing angles and reappears when orbiting further. The committed
`capture/stub/fixtures/model.glb` fixture is a single planar triangle, so normal back-face culling
explains that observation rather than a touch/OrbitControls failure. Safari reports the downloaded
GLB as a binary file it cannot preview; that is expected and does not prevent retrieval.

## Notes and decisions

2026-10-12: The viewer is mounted only when C-10 returns a terminal reconstruction result. The
production path uses three.js `GLTFLoader` plus `OrbitControls`; the loader is injectable so URL
and fallback behaviour can be tested under happy-dom without pretending WebGL exists there. The
download link is created before the WebGL renderer starts, so renderer/decoder failure never
removes access to the raw GLB. The viewport resizes with the browser, one-finger touch rotates,
and two-finger touch dollies/rotates for pinch zoom.

2026-10-14: Real-device manual check completed on iPhone Safari / iOS 26.5.2. Rendering, orbit,
pinch zoom, and GLB retrieval all worked. The temporary disappearance at some orbit angles is the
expected back-face behaviour of the one-triangle canned GLB fixture, not a viewer regression.

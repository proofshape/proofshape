## Why this exists

A buyer can't do anything in ProofShape today. Manual §4: "There is no buyer side and no order
storage." The proposal's first step is buyer setup: "Upload the CAD (STL/OBJ/GLB), enter the
tolerance and the critical features … and generate a capture link plus a printable reference sheet
for this purchase order" (§3). Without it, no session ever has a CAD, so no verdict can exist
(D-004). A-03's parsed spec also needs an editable table to land in: "The buyer confirms before
anything is used" (§7.4).

## Acceptance criteria

- **A buyer page in the same app.**
  - `capture/buyer.html` and `src/buyer.ts`, added to `vite.config.ts`'s build inputs, which have
    no second page today.
  - It takes:
    - a CAD file;
    - an editable table in §7.4's shape: `name`, `kind` (hole, face, edge or overall),
      `tolerance_mm` above 0, and `critical`, plus the assumptions;
    - the placement note ("hole A toward the sheet's arrow", which I-05 left to this story);
    - the buyer's own reference.
  - It sends them with R-34's `createOrder`. The table is the proposal's "manual tolerance form"
    (§9). A-03 later fills the same table and never bypasses it.
- **Success and failure.**
  - On success it shows the order code, the CAD's size in mm as the service read it, and the
    capture link, `?order=<code>` on the app's own address.
  - On failure it shows the service's error message and keeps the form filled in.
- **No claim that a tolerance can be met.** The page says tolerances aren't yet checked against the
  method's noise floor (I-09, not built). It shows no Unverifiable flag, and nothing on it says a
  tolerance is achievable (D-003).
- **It runs on the mock.** The stub gains `createOrder` and `getOrder` from R-34's examples, so the
  page works under `npm run dev` with no service.

## Tests

`buyer.test.ts` (happy-dom):
- table edits produce exactly §7.4's JSON;
- an empty name, a tolerance that is 0, negative or not a number, or a wrong file extension blocks
  the submit with a named message;
- the multipart body, with the spec part sent as JSON;
- what success and failure show;
- the capture link, with and without a base path (C-21);
- the stub routes.

Nothing here needs a real device.

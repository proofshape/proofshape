## Why this exists

`contracts/openapi.yaml`'s `getReconstruction` has never been called from `capture/` — C-01's
stub only covers the three session-lifecycle routes it needed for its own story, not this one.
The sprint plan's own §4 names a "mock service (S1): ~40 lines answering every call in the frozen
contract with a canned GLB and a canned verdict... frees the capture front end from the GPU
service," but nothing has built it. Without this, nothing after `finishSession` has anywhere to
go, and C-11's viewer would have nothing real to point at except R-14's full backend.

## Acceptance criteria

- `api.ts` gains `getReconstruction(sessionId)`, matching `ReconstructionResult`'s
  `pending`/`complete`/`failed` status.
- After `finishSession`, the page polls `getReconstruction` until `complete` or `failed`, or a
  bounded number of attempts times out with its own message. While `pending`, it shows that
  state rather than nothing; once `complete`, it shows `reference_tier_used`, `metric` (and "no
  dimensional claims" when false, per §6.1), `observed_fraction`, and any `warnings`.
- The stub gains a working `/finish` (flips status to `finished`, matching `createSession`'s
  existing session store) and a working `/reconstruction` route that answers `pending` once, then
  `complete` with a canned `glb_url` pointing at a small fixture GLB the stub serves itself, and
  the rest of its fields from `contracts/examples/*.json` — this is the sprint plan's promised
  mock service, built once here rather than a third time, piecemeal, in C-11 or C-13.

## Tests

Unit-test the polling logic against the extended stub: `pending` → `pending` → `complete`
renders the summary fields correctly; a `failed` status shows the failure rather than freezing on
"pending"; exhausting the attempt budget without resolution shows the timeout message instead of
polling forever. No manual-check exception — this is fetch/polling logic with no DOM or device
dependency beyond what `page.test.ts` already exercises.

2026-10-11: Reworked the implementation after review so C-10 is wired into the current
`mountAppShell` flow rather than the superseded C-01 upload-page mount point. The live shell now
exposes "Finish session" and, after a successful `finishSession`, polls and renders reconstruction
status. The button can return the existing "too few frames" contract error today; once C-05/C-09
feed accepted frames into the same session, the identical live path proceeds to reconstruction.

The default polling budget is 300 attempts at 2 seconds (about ten minutes), covering slower
supported backends as well as the measured R-15 path. Timeout or fetch-error states expose a retry
control that resumes polling the same finished session without calling finish again. Tests override the delay
and attempt count so CI stays fast while still covering pending → pending → complete, failed, and
timeout outcomes.

The existing C-01 contract stub is extended instead of introducing another mock server. It loads
the committed reconstruction examples, preserves HTTPS when served through the device dev server,
and serves a minimal valid glTF 2.0 triangle GLB with a real scene and mesh so C-11 has something
renderable rather than only magic bytes. A non-metric result explicitly renders "No dimensional
claims", preserving the project rule that unobserved or unmeasured geometry never becomes a
measurement claim.

No frozen OpenAPI change was needed. The new TypeScript interfaces mirror the existing
`ReconstructionResult`, `ReferenceTier`, and `ScaleAgreement` schemas.

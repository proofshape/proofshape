## Why this exists

C-05 produces a frame paired with a gyro reading. C-06 grades a frame as sharp, well-exposed and
not a duplicate. C-07 tracks which orbit slot is covered and which to aim at next. None of the
three has ever called another — each was built and tested in isolation on purpose, the same
"don't block on another story's already-shipped code" reasoning C-04's notes recorded. Nothing
today turns a live stream into an uploaded, server-accepted frame, and nothing feeds a result
back into the arrow. This story is that wiring, and the walking skeleton (M1) has nowhere to go
without it.

## Acceptance criteria

- A "capture" action grabs a still plus the live gyro reading from C-05, and runs it through all
  three C-06 checks before any network call. A failing check shows its specific reason
  (`frame_rejected_blur` / `frame_rejected_exposure` / `frame_rejected_duplicate`) and nothing is
  uploaded.
- A still that passes the local gate is uploaded via `api.ts`'s `uploadFrame` with that same gyro
  reading. A `202` marks the orbit slot that reading corresponds to as covered in C-07's tracker
  and advances the arrow; a `422` shows the server's reason and does not mark anything covered.
- `finishSession` is callable once at least one frame has been accepted. Calling it before that
  surfaces the existing `too_few_frames` message C-01 already renders from the `409` response —
  this story does not add a second, client-side minimum that could drift from the server's own
  (`recon/service.py`'s `MIN_FINISH_FRAMES`).
- The contract stub works over HTTP/2, which is what `npm run dev:device` serves to a real phone:
  `createSession` and `uploadFrame` answer per the contract instead of a 500, and the
  reconstruction `glb_url` names the host the phone actually used, not `127.0.0.1`. Both are
  broken today (2026-10-14 note below), and this story's manual check is the first to need them.

## Tests

The wiring itself is state-transition logic over functions each already proven independently
(C-05's grab, C-06's checks, C-07's tracker, C-01's `api.ts` calls) — testable against the
contract stub with the existing happy-dom `getUserMedia`/`deviceorientation` mocking pattern.
Cover: a gate rejection for each of the three reasons never calls `uploadFrame`; an accepted
upload marks exactly the slot its gyro reading falls in, not an adjacent one; a `422` response
does not mark coverage; `finishSession` is blocked-and-messaged before any acceptance and callable
after one; the stub given an HTTP/2-shaped request (pseudo-headers in `req.headers`, `:authority`
in place of `host`) answers `createSession` normally and returns a `glb_url` with that authority.

Manual check (device, iOS/Safari version, steps, result): walking through accept and each
rejection reason on a real phone, confirming the arrow only advances on acceptance, and confirming
a still grabbed from the live stream and drawn to canvas is not mirrored or rotated in a way the
synthetic fixtures in C-06's own tests would not reveal — happy-dom renders no video at all, so
this is the same class of exception C-02 and C-03's device checks already rely on.

## Notes and decisions

2026-10-15: Implemented in `capture/src/camera.ts` (new `encodeFrameAsJpeg`, a cached-canvas
rework of `capturePixelsFromVideo`), `capture/src/shell.ts` (the capture loop itself, wired into
the existing `#shell-capture-button`), and `capture/stub/contract-stub.ts` (the HTTP/2 fix).

**No new "pure capture-loop" module.** The gate → encode → upload → mark-coverage orchestration
lives directly in `shell.ts`'s `captureButton` click handler, as an async function — matching
`startButton`/`finishButton`'s existing shape. `frame_gate.ts`/`orbit.ts`/`api.ts` stay pure and
separate specifically so `shell.ts` can be "the one real flow" wiring them; there's no precedent
anywhere in this codebase for a dedicated orchestration file.

**Gate checks run blur → exposure → duplicate, first failure wins** (the story's own criteria
order). The rejection status shows the error *code* alongside the message, not just the message —
`checkDuplicate`'s own message ("Gyro delta ... are both below their thresholds") never actually
says "duplicate," so the code is what makes the reason identifiable, matching the acceptance
criteria's explicit naming of all three codes.

**`mountGyroOverlay` is mounted once at shell setup, and remounted at the top of every `Start`
click.** `overlay.ts`'s own comment (from C-07's PR #120 review) already anticipated this exact
remount ("a second mount on the same container -- e.g. C-09's capture loop re-mounting on retry
-- can't leak the first mount's listener"). A closure-scoped `lastAcceptedForGate` (the last frame
that passed the *local* gate, separate from `state.lastCapturedFrame`) resets alongside it, so a
frame locally accepted under an abandoned session (bad order code, retried) can't anchor
duplicate-detection or orbit coverage for the next, real session.

**HTTP/2 contract-stub fix**, this story's own last acceptance criterion: `toWebRequest` now skips
any header key starting with `:` before building the WHATWG `Headers` (HTTP/2 pseudo-headers like
`:method` made `Headers.set` throw, 500ing `createSession`/`uploadFrame`); `handleReconstruction`
falls back to `req.headers[":authority"]` when `.host` is absent, so `glb_url` names the phone's
real host instead of `127.0.0.1`. Confirmed against a real Node `http2.createServer()` that this is
exactly the header shape Vite's `dev:device` (which uses `http2.createSecureServer` whenever
`basicSsl` is active) actually produces. Tested by calling `stub.handle(fakeReq, fakeRes)` directly
— no real socket/TLS needed, since `handle` is already designed to be callable that way.

**Nine items from TabeenRaoof's PR #137 review (C-05/C-11 review carryover + this story's own
HTTP/2 criterion), each addressed:**

1. *HTTP/2 stub fix* — done, above.
2. *Camera stayed on after a failed session* — fixed: by the time the camera grant resolves,
   whether the session succeeded is already known (the session `await` runs first in the function
   body). If it failed, the just-granted stream is stopped immediately rather than attached to the
   preview — the `getUserMedia` call itself still fires first and un-awaited (item 4), only what
   happens with the *result* changed.
3. *Confirm on a device that Finish turns the camera off* — now reachable (item 1 unblocks it);
   see the manual-check record below.
4. *Keep the iOS gesture intact* — preserved; the new per-session resets (overlay remount, gate
   state) and the session-failure camera release all happen after the gesture-critical calls, not
   before them.
5. *"Camera started." stayed on screen after release* — `releaseCamera()` now also sets a generic
   "Camera stopped." status; the one caller with a more specific reason (`play()` rejecting) calls
   `releaseCamera()` first, then overwrites it with that reason.
6. *Capture became available too early* — `updateCaptureAvailability()` now gates on a new
   `state.cameraPlaying` (true only once `play()` resolves) and `state.latestGyro !== null` (a real
   reading, not just `gyroGranted`, which can be true with no sensor ever firing). Called from the
   orientation listener too, so the first reading — not just the grant — can flip capture on.
7. *A new canvas for every capture* — `capturePixelsFromVideo` now caches one canvas+context per
   video element in a `WeakMap` (not module-level state — this codebase deliberately avoids that;
   see `gyro.ts`'s own `listening` flag), resized only on a real dimension change, with
   `{ willReadFrequently: true }` since every draw is immediately followed by `getImageData`.
   `encodeFrameAsJpeg`'s own canvas stays uncached — it only runs for gate-passing frames, far
   less often than every capture attempt.
8. *Orientation data point* — C-05's real capture was "480x640" (portrait); recorded as the
   baseline for this story's own mirror/rotation manual check, below.
9. *(Optional) Finish's `try` also caught polling errors* — `releaseCamera()` and
   `runReconstructionPolling()` now run outside the `try` that wraps `finishSession` itself, so a
   post-finish failure (e.g. in the reconstruction poll or the viewer it rebuilds) is no longer
   mislabeled "Could not finish session" or allowed to wrongly re-enable Finish.

**A latent test-isolation bug surfaced along the way**: `shell.test.ts`'s outer `afterEach` never
called `vi.restoreAllMocks()`, so `vi.spyOn` calls (canvas context/`toBlob`, `fetch`) leaked across
tests. Harmless while nothing spied on a shared prototype method with per-test return values, but
this story's heavier canvas/fetch spying surfaced it — an unrestored spy from one test silently
answered another test's calls. Fixed by adding the missing `vi.restoreAllMocks()`.

**The hand-built HTTP/2 request fake's multipart body had to come from a real `FormData`/`Request`,
not hand-rolled bytes.** A manually-assembled multipart body around the raw JPEG magic bytes
(`0xFF 0xD8 0xFF` — not valid UTF-8) desynced undici's own parser (it found the `frame` part but
never `gyro`). Building a real `FormData`, constructing a real `Request` from it, and reading back
its generated body + `content-type` guarantees the bytes and the parser agree, since the same
engine produces and consumes them.

2026-10-14 (added before anyone claimed this story, from the PR #131 review): phone-testing C-11
under `npm run dev:device` found two bugs in `capture/stub/contract-stub.ts`, both because Vite
serves HTTPS over HTTP/2. (1) `toWebRequest` copies every `req.headers` entry into a WHATWG
`Headers`; HTTP/2 adds pseudo-headers (`:method`, `:path`, `:authority`, `:scheme`) that
`Headers.set` rejects, so `createSession` and `uploadFrame` — the two routes that go through
it — return a 500 `stub_violation`. (2) `handleReconstruction` builds `glb_url` from
`req.headers.host`, which HTTP/2 does not send (it carries `:authority`), so the URL falls back
to `https://127.0.0.1/...` with no port — on a phone, that is the phone itself. Both reproduce
with `curl --http2` against `dev:device`, and `--http1.1` works. Folded in here rather than filed
as its own story because this is the first story whose own check needs the stub on a phone:
C-11's check uses `?viewer-demo=1`, which goes through neither path, and C-13 tests against the
deployed service instead. Likely fix: skip keys starting with `:` in `toWebRequest`, and fall
back to `req.headers[":authority"]` when `host` is missing. Repro:
https://github.com/proofshape/proofshape/pull/131#issuecomment-6179785848

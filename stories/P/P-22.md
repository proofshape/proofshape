## Why this exists

Only code stories carried actual hours, so the proposal, the plan, the process rules, the
backlog write-ups, the documents and the reviews were missing from every hours total.

## Acceptance criteria

- D-052 records the P lane, its boundary with other stories, and how past work is recorded.
- `scripts/check_story_states.py` accepts `—` as an estimate on a P story, reports it on any
  other lane, and still rejects anything else that isn't `<number> h`, where the number has at
  least one digit.
- P-01..P-23 have story files and index rows, and the checker passes on them.
- The glossary's Lane entry and the story template mention the P lane.
- `AGENTS.md`'s definition of done points P stories to D-052, so an assistant reading only
  `AGENTS.md` doesn't apply the code rules to documents.

## Tests

The checker change has tests in `tests/test_check_story_states.py`, written before the pattern
changed. The new behaviour, a `—` row read and checked like any other, failed first and passes
now. The guard, `-`, a blank or `TBD` still reported as unreadable, is three parametrised cases
that passed before the change and still pass: they pin down what the looser pattern must not
start accepting. Review then found the hours pattern read `.. h` and `. h` as estimates (a gap
from before this story). Those two cases were added to the guard, failed, and pass now that
the number needs a digit. Three more cases (`2.5 h`, `10 h`, `3h`) check that real estimates are
still read. A second review round found `—` accepted on any lane, though D-052 allows it only
for P stories. Three cases (an F, an R and a C story with `—`) failed first and now pass:
the row is still read, and reported with its own reason. The story files and D-052 are a
written check.

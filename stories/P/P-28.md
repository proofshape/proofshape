## Why this exists

Three problems in the project's process tooling:

- **The checker can false-pass (#194).** `check_story_states.py --fix` exits 0 as soon as it
  applies any fix, even when it found problems it can't fix. When the index row isn't `Blocked`,
  it also reports an index edit it didn't make.
- **The decision-number snippet can hand out a taken number (#195).** The snippet AGENTS.md gives
  takes the *last* header in `docs/decisions.md`, not the highest, and the file is out of order by
  design.
- **Nobody else can build the deck (#201).** `scripts/build_midterm_deck.js` requires a file from
  one person's home directory, and none of the three generator scripts has a test.

## Acceptance criteria

- `--fix` exits 1 when unfixed problems remain, and reports an error when the index row it meant
  to change didn't match.
- The AGENTS.md snippet sorts numerically before taking the last number.
- `build_midterm_deck.js` builds from a clean checkout on a second member's machine, with its
  theme step vendored into `scripts/` or made optional with a clear message.

## Tests

Code inside a P story keeps the normal rules (D-052): tests written with it, and a second-member
run.

- the checker with one fixable story plus one owner mismatch, asserting the exit code;
- a smoke test that builds each of the three generator scripts to a temporary file.

The AGENTS.md change is a document; the reviewer checks it by running the snippet against a
decisions file whose last header isn't its highest.

## Notes and decisions

- Closes #194, #195 and #201 (`Fixes #194`, `fixes #195`, `fixes #201`).
- `scripts/` has no Node test setup, and CI only runs Node in `capture/`. Where the generator
  smoke test runs (a CI job, or pytest calling node) is the owner's call. Say so in
  `scripts/README.md`, which doesn't list the midterm scripts yet.
- `build_midterm_deck.js` belongs to P-20, which is Done. Changing it after it merged is P-lane
  work under D-052's boundary.
- #201 was fixed by making the theme pass optional (a try/catch around the `require`, falling
  back to a no-op with a clear console message), confirmed with the team rather than vendoring
  Anthropic's internal skill code into this public repo.
- The generator smoke test (`tests/test_generator_scripts.py`) runs as a normal `pytest` test,
  not a separate CI job — matching how `tests/test_download_golden_capture.py` already shells
  out to a non-Python script. `.github/workflows/python-ci.yml`'s `pytest` job now installs
  `scripts/node_modules` before running tests (a new `actions/setup-node@v4` + `npm install`
  step, Node 24 to match `typescript-ci.yml`), so this is real CI coverage, not skip-only. A
  `skipif` still protects a contributor running `pytest` locally without having run
  `npm install` in `scripts/` first — the only place in the Python suite that depends on Node
  tooling.
- Both #194 fixes verified by mutation testing (break each one, confirm only the new tests fail,
  revert). #201's fix verified the same way: reverting the try/catch to an unconditional
  `require` makes exactly the midterm-deck build test and the theme-skip test fail, nothing else.
  #195 is a markdown snippet, not a pytest target — verified directly against the real
  `docs/decisions.md` (which already has an out-of-order D-30/D-25 pair later in the file):
  the old `tail -1` and the new `sort -t- -k2,2n | tail -1` both happen to return `**D-055`
  today (the file's current tail is still in order), but the sorted version is the one that
  stays correct if that changes.

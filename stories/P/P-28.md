## Why this exists

Three problems in the project's process tooling:

- **The checker can false-pass (#194).** `check_story_states.py --fix` exits 0 as soon as it
  applies any fix, even when it found problems it can't fix. When the index row isn't `Blocked`,
  it also reports an index edit it didn't make.
- **The decision-number snippet can hand out a taken number (#195).** The snippet AGENTS.md gives
  takes the *last* header in `docs/decisions.md`, not the highest, and the file is out of order by
  design.
- **Nobody else can build the deck (#201).** `scripts/build_midterm_deck.js` requires a file from
  one person's home directory, and none of the three generator scripts has a test.

## Acceptance criteria

- `--fix` exits 1 when unfixed problems remain, and reports an error when the index row it meant
  to change didn't match.
- The AGENTS.md snippet sorts numerically before taking the last number.
- `build_midterm_deck.js` builds from a clean checkout on a second member's machine, with its
  theme step vendored into `scripts/` or made optional with a clear message.

## Tests

Code inside a P story keeps the normal rules (D-052): tests written with it, and a second-member
run.

- the checker with one fixable story plus one owner mismatch, asserting the exit code;
- a smoke test that builds each of the three generator scripts to a temporary file.

The AGENTS.md change is a document; the reviewer checks it by running the snippet against a
decisions file whose last header isn't its highest.
